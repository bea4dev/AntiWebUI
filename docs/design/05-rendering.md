# 05. レンダラ（anti-webui-wgpu）

## 入力: Scene

core はフレームごとに `Scene`（描画コマンドの列）を生成する。座標は物理 px。

```rust
enum Primitive {
    Shadow(Shadow),      // ボックスシャドウ
    Quad(Quad),          // 背景・枠線・角丸・キャレット・選択ハイライト・下線
    Glyphs(GlyphRun),    // フォント参照・サイズ・座標・色
}
```

どのプリミティブも自分のクリップ矩形を持つ（push/pop 型のクリップスタックは使わない）。

- `Quad`: 整数矩形、背景色、辺ごとの枠線幅（整数）、枠線色、4 隅の角丸半径（f32）、影（オフセット・ぼかし・色）。
- `GlyphRun`: フォントデータ（`Blob` + index）、物理フォントサイズ、正規化座標（可変フォント）、合成（太字・斜体）、色、各グリフの `(id, x, y)`。

## GPU 側

- **矩形パイプライン**: インスタンス描画。フラグメントシェーダで角丸矩形の SDF を評価し、枠線と背景を 1 パスで描く。影はガウスぼかしを近似した解析式で描く。
- **グリフパイプライン**: インスタンス描画。RGBA8 アトラス 1 枚。単色グリフはカバレッジを、カラー絵文字はプリマルチプライド色を格納し、インスタンスのフラグで区別する。
- **クリップ**: インスタンスごとにクリップ矩形を持たせ、シェーダで判定する（バッチを分けずに済む）。
- **順序**: Scene の順に、同じパイプラインが続く区間を 1 ドローコールにまとめる。
- **ブレンド**: プリマルチプライドアルファ。ブラウザと同じくガンマ空間（非 sRGB フォーマット）で合成する。

## グリフキャッシュ

- キー: `(フォント blob id, フォント index, グリフ id, 物理サイズ（1/64 px 量子化）, サブピクセル x（1/4 px）, 合成フラグ, 可変フォント座標のハッシュ)`。
- ラスタライズは swash。ソース優先順: カラーアウトライン → カラービットマップ → アウトライン。
- アトラスはシェルフパッキング。満杯になったら拡張し、それでも足りなければクリアして次フレームで再構築する。

## ダメージトラッキング

変更された領域だけを描き直し、その範囲を OS のコンポジタにも伝える。Chromium と同等の効率を目標にする。

### 1. 変更領域を求める（core）

- ペイントは Scene を**チャンク**に区切って出力する。チャンクは「あるノードのある部分」を表すキー `ChunkKey(node, part)` と、連続するプリミティブの範囲を持つ（Chromium の PaintChunk に相当）。
  - `part` は「自身の背景・テキスト」「子の後に描くもの（スクロールバー・アウトライン）」「キャレット」を区別する。キャレットを独立させることで、点滅のたびに入力欄全体が汚れるのを防ぐ。
- 前フレームの Scene と比較して変更矩形を求める（`damage::diff`）。
  1. 新しいチャンクを順に、前フレームの同じキーのチャンクと対応付ける。
  2. 対応が無い（追加）→ 新しい範囲を汚す。前フレームにしか無い（削除）→ 古い範囲を汚す。
  3. 対応があり、前フレームでの並び順が逆転している → 両方の範囲を汚す（重なりの描画順が変わるため）。
  4. 内容が異なる → プリミティブ数が同じなら、異なるプリミティブの新旧の範囲だけを汚す。数が違えばチャンク全体の新旧の範囲を汚す。
- 画面サイズや背景色（clear）が変わったら全面を汚す。
- **正しさ**: 汚れていないピクセルは、同じ内容・同じ相対順序のプリミティブだけで覆われるので、前フレームと同じ結果になる。
- プリミティブの範囲:
  - 矩形: `rect ∩ clip`（アンチエイリアスは矩形の内側で完結する）。
  - 影: シェーダと同じく `blur × 1.5 + 1` だけ外側に広げる。
  - グリフ: フォントの `head` テーブルの外接矩形（全グリフを包む）にグリフ位置を足して求める。合成太字・斜体・サブピクセル位置の分の余白を加える。
- 矩形が多すぎると GPU 側のコストが増えるので、重なる矩形や、併合しても無駄な面積が小さい矩形をまとめ、最大 8 個に抑える。

### 2. 部分描画（renderer）

- `Renderer::render_damaged(…, damage)` は、描画先の内容が「前回までの正しいフレーム」である前提で、変更矩形の中だけを描き直す。
  - `LoadOp::Load` で前の内容を残す。
  - 矩形ごとに scissor を設定し、ブレンド無しのパイプラインで clear 色を塗ってから、その矩形に掛かるプリミティブを描く。
  - どの矩形にも掛からないプリミティブは、インスタンスを作る段階で捨てる。
- **buffer age**: 表示用バッファは複数枚を順番に使うため、あるバッファの中身は「k フレーム前」のものである。描き直す範囲は、直近 k フレーム分の変更矩形の和にする（`DamageHistory`）。age が分からないバッファは全面を描く。
- 変更矩形が空なら、そのフレームは描画も提示もしない。

### 3. 提示とコンポジタへの通知（presenter）

wgpu の Surface は buffer age も変更範囲の通知も公開していないので、OS ごとに表示用バッファを自前で管理する presenter を持つ。core と renderer は共通で、presenter だけが OS ごとに異なる。

| OS | バッファ | 変更範囲の通知 | 状態 |
|---|---|---|---|
| Wayland | dmabuf を自前で確保（Vulkan） | `wl_surface.damage_buffer` | 実装（[06](06-platform-wayland.md)） |
| Windows | DXGI flip model のバッファ / DirectComposition | `Present1` の dirty rects、`IDCompositionSurface::BeginDraw` | M3 |
| macOS | IOSurface を自前で回し `CALayer.contents` に設定 | 矩形単位の API は無い。レイヤー分割で代替 | M3 |
| その他 / フォールバック | wgpu Surface | 無し（毎回全面） | 実装 |

自前管理ができない環境（GL バックエンド、dmabuf 非対応のコンポジタなど）では、wgpu Surface に全面描画するフォールバックを使う。この場合も「変更が無ければ描かない」は効く。

### 今後

- ペイント（Scene 生成）とスタイル解決は、まだ毎フレーム全ノードを走査する（CPU 側の差分化は別途）。
- スクロールは、今は動いた内容全体が汚れる。Chromium のようにスクロール内容をレイヤーとしてキャッシュし、合成だけで動かすのは別の段階で行う。

## 表示

- サーフェス形式は `Bgra8Unorm` / `Rgba8Unorm`（非 sRGB）を優先。
- バックエンドはまず Vulkan / Metal / DX12 を試し、アダプタが無いときだけ GL に落ちる（Mesa の GL は LLVM を読み込むため重い）。環境変数 `WGPU_BACKEND` で上書きできる。
- PresentMode は `Mailbox` → `Fifo` の順で選ぶ。フレームの律速は Wayland のフレームコールバックで行う（非表示ウィンドウで WSI がブロックするのを避ける）。
- オフスクリーン描画（テクスチャ → PNG）をサポートし、テストとスクリーンショットに使う。

## デバッグ

- `ANTIWEBUI_DEBUG_DAMAGE=1` を指定すると、フレームごとに変更矩形・buffer age・描き直した面積の割合を標準エラーに出す。
- `ANTIWEBUI_PRESENT=surface` で、自前の presenter を使わず wgpu Surface（全面描画）に固定する。

- `ANTIWEBUI_DUMP_FRAME=out.png` を指定すると、表示したフレームと同じ Scene をオフスクリーンで描画して PNG に書き出す（画面キャプチャ無しで実バッファの内容を確認できる）。
- `anti_webui_app::headless::{render_png, render_driven_rgba}` で、合成イベントを流した後の状態をスナップショットにできる。
