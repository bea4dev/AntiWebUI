# 11. GPU の塗りの効率（Chromium との差）

大きな箱の塗りに全ピクセルで万能シェーダーを走らせていたのをやめ、**単色で済む部分は単色の経路で描く**。

## 計測

AMD Radeon 880M、ShojiWM、120 Hz、電池駆動。同じ内容のページと `bench_pacing` を、約 1650×1620 のウィンドウで比べた。

前回（`10-frame-pacing.md`）の「60 層と 120 層で Chrome は 119fps」は、**ベンチの作りが原因で比較になっていなかった**。アルファの変化が小さく、8 ビットに丸めると同じ値になるので、Chrome はほとんど描き直していなかった（トレースでは BeginMainFrame 911 回に対してラスタ 164 回）。毎フレーム必ず色を変えると Chrome も落ちる。

| 負荷（fps） | Chrome | AntiWebUI |
|---|---|---|
| 塗りのみ 120 層、角丸なし | 79.9 | 45.5 |
| 塗りのみ 120 層、角丸あり | 80.0 | 45.3 |
| 影のみ 120 層 | 77.9 | 85.0 |
| 影のみ 60 層 | 117.6 | 119.9 |

差は塗りだけにあり、影はこちらが速い。角丸の有無で変わらないのは、どちらもすべてのピクセルで角丸の距離計算をしているため。

## 方式

### 単色の経路

- 整数ピクセルのレイアウトなので、矩形の辺にアンチエイリアスは要らない。矩形は色をそのまま出すだけでよい。
- 専用のシェーダー（`vs_solid` / `fs_solid`）とインスタンス（矩形と色の 32 バイト）を持つ。
- 不透明な色はブレンドを切ったパイプラインで描く。ダメージ範囲のクリアも同じパイプラインを使う。
- 矩形のクリップは CPU 側で先に切る。

### 箱の分割

| 箱 | 分割 |
|---|---|
| 角丸なし、枠なし | 単色 1 枚 |
| 角丸なし、枠あり | 中央と枠の 4 辺、すべて単色 |
| 角丸あり、枠なし | 単色の帯 3 枚 + 角 4 つ |
| 角丸あり、枠あり | 中央が単色 + 周囲の帯 4 枚 |
| 角丸のクリップがかかる | 分割しない。ただし箱がクリップの角に届かないなら、クリップなしとして扱う |

- 分割した部分は重ならないので、描く順番は結果に影響しない。
- 単色の部分が小さい箱（小さなボタンや円など）は分割しない。インスタンスが増える分だけ損なので。
- 背景が透明なら中央を描かない（枠だけの箱）。
- 分割のために、万能シェーダーのインスタンスは「描く範囲（`area`）」と「形（`shape`）」を別に持つ。

### 8 ビットに丸める

ペイントで色を 8 ビットに丸める。画面に出ない色の変化では差分が出ず、描き直さない。ゆっくりしたフェードで効く。Chrome が上の計測で描き直さなかったのと同じ効果。

## 効果

変更前の版、変更後の版、Chrome を交互に、同じ条件で測った（各 8 秒、電池駆動、起動後 4 秒は除く）。このときコンポジタの負荷が高く（何もしていなくても GPU 使用率が約 48%）、上の表とは条件が違う。電力は SoC 全体。

| 負荷 | 変更前 fps / W | 変更後 fps / W | Chrome fps / W |
|---|---|---|---|
| 小さな変更のみ | 116.4 / 9.8 | 116.5 / 9.7 | 119.9 / 10.0 |
| 2000 行のスクロール | 119.9 / 10.1 | 119.9 / 10.0 | 119.9 / 10.1 |
| 塗りのみ 120 層、角丸なし | 42.6 / 22.2 | 75.5 / 17.1 | 71.2 / 17.1 |
| 塗りのみ 120 層、角丸あり | 41.6 / 22.4 | 74.5 / 18.3 | 70.6 / 22.3 |
| 塗りと影 60 層 | 56.1 / 23.0 | 73.6 / 20.7 | 66.3 / 22.0 |
| 塗りと影 120 層 | 33.6 / 23.8 | 41.6 / 20.1 | 40.6 / 21.1 |
| CPU 4 ms + 40 層 | 76.1 / 24.0 | 100.6 / 21.0 | 86.4 / 22.0 |
| 影のみ 120 層（3 回） | 77.3〜77.9 / 24.8 | 78.9〜79.3 / 25.0 | 69.9〜72.1 / 23.5 |

- Chrome の fps は `requestAnimationFrame` の回数、こちらは画面に出た回数。
- 「小さな変更のみ」の 116.5 は、動く箱の位置が変わらないフレームを描かないため（描く必要がない）。
- GPU が飽和する負荷は、同じ版でも 1 回だけ 10fps ほど低く出ることがある（影のみ 120 層で 67.4 と 68.0）。比べるときは繰り返す。
- 正しさは、すべてを万能シェーダーで描いた結果との比較で確認している（`boxes_in_parts_look_the_same_as_through_the_quad_shader`）。差は 1 段階以内で、万能シェーダー側の丸め誤差。

## 残る課題

- 角丸のクリップがかかり、クリップの角に届く箱は分割しない。
- スクロールレイヤーの合成はグリフのパイプラインのまま。全画面の 1 枚を毎フレーム描くので、専用の経路にする余地がある。
- 影の 9 パッチ化はしていない。今の時点で Chrome より速いので急がない。
- NVIDIA では未計測。
