# 40. 数式（LaTeX）

Markdown の `$…$` と `$$…$$` を、JavaScript も WebView も使わずに描く。比べる相手は Chromium の KaTeX（Obsidian、Typora は MathJax、VS Code は KaTeX）で、見た目は KaTeX に、速さと軽さはそれより上を目指す。

## 調べたこと（2026-11-14）

### ライブラリ

| 候補 | 中身 | 判断 |
|---|---|---|
| **RaTeX** 0.1.15（MIT、フォントは OFL） | KaTeX の parser と layout を Rust で作り直したもの。出力は em 単位の描画の列（グリフ、線、矩形、パス） | **採用** |
| katex-rs + katex-native | KaTeX の HTML 出力に、Rust に移した KaTeX の CSS を当てて描画の列にする | HTML と CSS を経由する遠回りで、katex-native は出たばかり（★2） |
| math-core → formulary | LaTeX → MathML、MathML Core を OpenType MATH で組む | Chromium の MathML と同じ作りだが、見た目は KaTeX より素朴で、formulary は★3 |
| latex-rust、mathra | TeX の規則を独自に実装 | 作者 1 人。latex-rust は Rust 1.99 が要り、今の 1.96 では作れない |
| mitex + typst | LaTeX → Typst で組む | 数式だけを取り出せず、typst-library だけで依存が 59 個 |
| `katex` crate、katex-v8 | KaTeX を QuickJS や V8 で動かす | JavaScript なので対象外 |
| tectonic、MicroTeX | TeX エンジン、C++ | 重すぎる、Rust から使えない |

### RaTeX と Chromium の KaTeX 0.19.1 を比べた

数式 77 個（日常の式、行列、cases、align、`\left\right`、アクセント、mhchem、CD、`\newcommand`、日本語の `\text`、わざと誤った式 3 個）を、headless の Chromium の KaTeX と、RaTeX 付属の PNG の描画で並べた。

- **形:** 74 個中 62 個は、幅が KaTeX と 0.03 em 以内で同じ（差の中央値 0.002 em）。目で見ても区別がつかない。
- **違い:**
  - `\tag` が右端でなく式の頭に描かれる（RaTeX の issue #175）。
  - 添字つきの根号 `\sqrt[3]{}` の前と、`\dots` の間が 0.33 em 広い。
  - `\overbrace` の並びは 0.33 em 狭い。
  - 分数の直後の括弧、cases、binom などで 0.08〜0.22 em ずれる。
- **受け付ける式:** KaTeX と同じ式を受け付け、同じ式を拒んだ（`\R` の再定義のエラーまで同じ）。エラーには位置がつく。
- **速さ（74 個）:**
  - RaTeX は parse と layout を合わせて 1.2 ms（中央値 12 µs/式、最大 101 µs）。最初の 1 式も 0.45 ms で済む。
  - Chromium の KaTeX は、同じ 74 個を 1 ページに置くと、2 回目以降で約 35 ms（作る 10 ms、スタイルとレイアウト 25 ms）、1 回目で 120〜150 ms かかる。
- **大きさ:** parser と layout で、strip したバイナリが 3.4〜4.0 MB 増える。多くは mhchem のための regex、fancy-regex、serde_json で、regex と serde_json は Markdown のクレートがすでに持っている。

## core: `drawing`

```rust
let mut d = Drawing::new(width, ascent, descent);  // em 単位。y はベースラインから下向き
d.items.push(DrawingItem::Glyphs { font, size, color: None, glyphs });   // None は文字の色
d.items.push(DrawingItem::Rect { x, y, width, height, color: Some(red) });
d.items.push(DrawingItem::Path { geometry, rule, stroke: None, color: None });
drawing(Arc::new(d)).em_scale(1.21)                 // 1 em = 継承した文字サイズ × 1.21
```

- 決まった描画の列を、ノードの文字サイズを 1 em として描く。中身は `Arc` で共有し、同じ式は同じものを使い回す。
- 大きさは画像と同じ置換要素として決まる（幅 × (ascent + descent) em を物理ピクセルに丸める）。`w`、`h`、余白、枠もふつうに効く。
- 色が `None` のものはノードの `color` で塗る。`\color` のない数式は、周りの文字の色、テーマ、`hover` に従う（引用の中では引用の薄い色になる）。
- 描き方:
  - **グリフ:** 文字と同じ `Primitive::Glyphs` にする。アトラス、x の 1/4 画素の位置、y の丸めも文字と同じなので、周りの文字と同じ見え方になる。フォントは `static_font(&'static [u8])` で作り、プログラムで 1 つずつ持つ（レンダラーはフォントごとにグリフを覚える）。
  - **矩形（分数の線など）:** 物理ピクセルの境に揃え、太さは 1 px 以上にする。Chromium も枠の太さを 1 デバイスピクセル単位に丸めるので、線がにじまない。
  - **パス（伸びる矢印、括弧、`\cancel`）:** `Primitive::Path` にする。形は式を組むときに 1 度だけ作り、拡大率が同じなら GPU 側の結果も使い回す。線のパスの太さは em で持ち、1 px 以上にする。
  - 矩形はグリフの下、パスはグリフの上に描く（`\colorbox` の背景は下、`\cancel` の線は上）。
- **ベースライン:** 上端から ascent em の位置。`rich_text` の `inline` に入れると、`VerticalAlign::Baseline`（既定）で数式のベースラインが文字のベースラインに揃う。インラインボックスに自分のベースラインを持たせ（`BoxData::baseline`）、parley の `InlineBox::baseline` に渡す。今までどおり、ベースラインのないもの（画像）は下端が揃う。
- 透明度があるときは、重なる部品が透けないようにレイヤーにする（部品が 2 つ以上なら重なりうるとみなす）。

### `text::shape_glyphs`

KaTeX のフォントにない文字（`\text{日本語}` など）を描くために、文字列をアプリのフォントで 1 行に整形して、フォントごとのグリフの列と幅を返す。フォールバックはアプリの文字と同じ。

### ついでに直したこと

インラインボックスしかない `rich_text`（文字列が空）の幅が 0 になっていた。空の文字列は幅を取らない、という扱いがボックスにまで効いていたため。ボックスがあればその幅にした。

## `anti-webui-math`

```rust
math(r"\frac{a}{b}")                      // 文中の式（KaTeX の displayMode: false）
math(r"\sum_{i=1}^n i").display()         // 別行の式
    .text_size(18.0).text_color(c)        // div と同じスタイル
    .leqno()                              // 式番号を左に
    .first_number(4)                      // 自動の番号を 4 から
    .references(|label| numbers.get(label).cloned())   // \ref、\eqref が出す番号
    .on_reference(|label| go_to(label))   // それが押されたとき
rich_text(math(r"a + b = c").runs())      // 文中で、演算子の後で折り返せる部品に分けて
check(&tex, display)                      // Result<(), MathError>: 理由と位置（バイト）
equations(&tex, first)                    // 別行の式が自動で番号を振る行の数と、ラベルの番号
```

- **フォント:** KaTeX 0.19.1 の TTF 19 本（501 KB、OFL）をクレートに入れて `include_bytes!` で持つ。`ratex-katex-fonts` は `rust-embed` を引き込むので使わない。RaTeX が使わない `Caligraphic-Bold` は入れない。フォントは使われたものだけを `FontData` にする。グリフの番号は cmap から引く（`read-fonts`。core がすでに使っている）。KaTeX の CSS と同じく、フォントにない文字は `KaTeX_Main` で探す。
- **使う RaTeX:** `ratex-parser`、`ratex-layout`、`ratex-types`、`ratex-font`（`=0.1.15` に固定）。描画、SVG、システムフォントを探す `ratex-unicode-font` などは使わない。
- **キャッシュ:** ソース（参照を番号に置き換えたもの）、文中か別行か、最初の番号、参照があるときはその色をキーに、組んだ結果（エラーも）をスレッドごとに覚えておく（2048 個まで、超えたら全部捨てる）。`check` で確かめてから表示しても、組むのは 1 回である。
- **色:** RaTeX には負の色（ありえない色）を既定の色として渡し、それが付いて出てきたものを「文字の色」（`None`）にする。
- **KaTeX のフォントにない文字:** 1 度組んで、そういう文字があれば、`shape_glyphs` で測った幅を渡して組み直す（`layout_with_fallback_metrics`）。高さは KaTeX と同じく M の高さ（0.683 em、深さ 0）にする。そういう文字のない式（ほとんど）は 1 回で済む。描くときも同じフォントを使う。KaTeX は `\text` を `KaTeX_Main, "Times New Roman", serif` で描くので、`serif` で探す。
- **大きさと置き方:** KaTeX の CSS と同じく、周りの文字サイズの 1.21 倍を 1 em にする。別行の式は、`.katex-display` と同じく、文字の行の高さの 1 行に中央寄せで置く（`rich_text` の中のインラインボックス）。幅が足りないときは左から始めて横にスクロールする。上下の余白は付けない（Markdown のテーマが付ける）。
- **`\tag`:** パーサーは `\tag` を書かれた所に別のノードとして残すので、それを抜き出し、本体と番号を別々に組む。番号は行の右端（`leqno` なら左端）、本体は行全体の中央に置く（左右に同じ幅の空きを置く flex）。両方の高さを揃えて、ベースラインを合わせる。文中の式の `\tag` は KaTeX と同じくエラーにする。
- **エラー:** ソースをそのまま、KaTeX と同じ `#cc0000` で出す。

### 文中の式の折り返し

KaTeX は文中の式を、一番外の関係子（`=` など）と二項演算子（`+` など）の後で別々の `inline-block` に分け、その間でブラウザが折り返す。後ろの空白は演算子の側に付くので、次の行は項から始まる。同じにした。

- 式は 1 度だけ組み、一番外の箱の子の並びから切る位置を求めて、描画の列を x で切り分ける。部品ごとに組み直すと、端の演算子が「相手のない二項演算子」として普通の文字になり、空白が変わるため。
- 子の並びは「ノードの箱」と「クラスのあるノードの前に入る空白」である。RaTeX の `node_math_class` と二項演算子の取り消し（どちらも公開されていない）を写し、公開されている `atom_spacing` で空白の入る所を求めて、子とノードを対応させる。合わないときは切らない。
- `-c` の `-` のように相手のない二項演算子は普通の文字なので、その後では切らない。`{a + b}` のように群の中も切らない。`\\` と `\newline` では行を終える（`rich_text` の改行）。
- KaTeX が式の中に開いて組む群（`\color`、`\textcolor`、`\displaystyle` などのスタイル、`\large` などの大きさ）は、その中も同じく切る。群の箱の子を同じ規則で中のノードと対応させ（大きさの群は拡大率を掛けて）、開いた後の並びで二項演算子の取り消しと切る位置を決める。
- `\allowbreak` の後でも切る。演算子の後の空白に `\nobreak`、`~`（`\nobreakspace`）があれば切らない（KaTeX と同じ）。
- 部品はそれぞれの中身の高さと深さを持つ。parley はインラインボックスとインラインボックスの間で折り返せる（core に手を入れる必要はなかった）。
- `Math::runs` が部品を `Run` の列で返し、最初の部品だけがコピーで `$ソース$` になる。エディタは文中の式のソースの範囲を部品の数に分けて、それぞれを部品のノードに置き換える。エディタの行には改行を入れられないので、`\\` の所には行の幅いっぱいで高さ 0 の箱を置く。次の部品は次の行の頭から始まり、縦の位置は改行したときと同じになる。
- 別行の式は KaTeX と同じく折り返さない（横にスクロールする）。

### 式番号

KaTeX は自動の番号（`equation`、`align`、`gather` など）を CSS のカウンタで振るので、1 つのページの式は 1 から通しで番号が付く。RaTeX のパーサーは式ごとに 1 から振るので、こちらで振り直す。

- パーサーが作った番号（`(`、番号、`)` で、どれもソースの位置がない）を見分けて、`first_number` から振り直す。書かれた `\tag` は番号を取らない（LaTeX、KaTeX と同じ。RaTeX は取る）。`\nonumber`、`\notag` の行も取らない。
- 環境の行の番号は、RaTeX では表のすぐ右に置かれる。KaTeX と同じく行の端に置くために、組んだ箱から番号の列を抜き出し（`take_tags`）、各行のベースラインの高さに置いた番号の列の描画にして、`\tag` と同じく行の端に置く。
- 番号を振る環境は、一番外のほか、ベースラインに置かれる群（`\color`、`\left…\right`、スタイル、大きさ、`\boxed` などの枠、`\raisebox`）の中にあっても見つける。番号を振り直すのはパース結果の同じ群の中、抜き出すのは箱の同じ入れ子の中で、上下の位置と拡大率を足していく。抜いた分だけ、外側の箱（`\left…\right` の右の括弧の位置を含む）を狭める。
- **ラベルと参照:** RaTeX は `\label`、`\ref`、`\eqref` を知らないので、組む前にソースから取り出す（`source.rs`）。`\label{k}` は消して、一番外の環境の何行目（`\\` の数）にあったかを覚える。`\ref{k}` は `\text{番号}`、`\eqref{k}` は `\text{(番号)}` に置き換え、それぞれを専用の色（`#7a0e00` に番号）で囲む。組んだ後、その色のグリフを見つけてリンクの色に変え、x の範囲を覚えておく。分からないラベルは `??` にする。
- 押されたときは、押された x に最も近い参照（4 分の 1 em 以内）のラベルで `on_reference` を呼ぶ。参照のある式だけ、カーソルを手にする。
- `equations(tex, first)` は、式が自動で振る番号の数と、ラベルとその番号を返す。ソースごとに 1 から数えた結果を覚えておき、`first` の分だけずらす。式の前で番号の数が変わっても、組み直さない。

## Markdown
- **読み上げとコピー:** 役割は `Image`、呼び名はソース。`rich_text` の中では、コピーしたときに `$ソース$`（別行は `$$ソース$$`）が入る。

## Markdown

- `pulldown-cmark` の `ENABLE_MATH` を有効にする（feature `math` のときだけ。ないときは今までどおり文字のまま）。`$…$` は文中の式、`$$…$$` は別行の式になる。` ```math ` のコードブロックも別行の式にする（GitHub と同じ）。画像の alt の中の式はソースの文字にする。
- ` ```math ` は、読むときに「別行の式だけの段落」にする。
- `$$…$$` は段落の中の要素として来る。段落がそれだけなら別行の式のブロックにし、文と混じっていれば、そこで段落を分けて間に式を置く（式の前後の空白は落とす）。見出し、表のセル、リストの中の `$$…$$` は、`\displaystyle` を付けて文中に置く。
- テーマに `math`（文中の式）と `math_block`（別行の式の箱。既定は KaTeX と同じく上下に 1 em）を足す。
- 文中の式が読めないときは、段落の中にソースを赤で出す（文と一緒に折り返す）。
- エディタ（`markdown_editor`）は Obsidian と同じく、キャレットが触れていない式を描いた式にし、触れるとソースに戻す。文中の式はインラインのノード、それだけの段落の `$$` と ` ```math ` はブロック（Mermaid と同じ）。ソースのときは `$` を薄く、中身をコードのスタイルにする。分割エディタのプレビューは `markdown_view` なので、そのまま数式が出る。
- **式番号:** 文書を読むたびに、別行の式を文書の順に並べ（ソースの位置つき）、`equations` で番号とラベルを求める（`numbers.rs`）。番号もラベルも作らない式（`\begin`、`\tag`、`\label` を含まない式）は組まずに飛ばす。式のソースが前回と同じなら（ほかの所を打ったとき）、前回の結果を使い、位置だけを新しくする。
  - 式は `first_number` で文書の中の番号から振り、ラベルのある式はアンカーとして覚えておく。参照（`\eqref{k}`）を押すと、見出しへのリンクと同じく、その式までスクロールする。文書にないラベルは `on_link("#k")` に渡す。
  - ブロックを覚えておくキーに、そのブロックの式の最初の番号と、参照があればラベル全体のハッシュを混ぜる。前の式が番号を増やしたとき、ソースの変わらないブロックも作り直すため。
  - テーマの `math_leqno` で番号を左に置く。
  - エディタも、文書全体を読むとき（`top_blocks`）に同じものを求める。パーサーが返すソースの切れ端は写さずに使う。
- 入れ子のリストや引用を作る `block` は再帰するので、そこに足すビルダーは別の関数に出した。最適化しないビルドではビルダーの一時値がそれぞれスタックを取り、既存のテスト（`links_go_to_headings_or_out`）がスタックを溢れさせたため。

## 確かめたこと（2026-11-14）

- 単体テスト: 描画の列への変換（矩形、パス、KaTeX のフォント、文字の色）、`\color`、キャッシュ、エラーの理由と位置、`\tag`、KaTeX のフォントにない文字（math 6 個）。`$`、`$$`、alt の中の式（markdown 1 個）。
- `Ui` を通したテスト: `drawing` の大きさ（1.5 倍を含む）、文中のベースライン、描くもの（色、1 px の線、パスの変換）、ボックスだけの `rich_text` の幅（core 4 個）。文中の式のベースライン、別行の式の中央寄せと `\tag`、広すぎる式、エラー（math 4 個）。ビュワーの `$`、`$$`、` ```math `、エラー、エディタで式に入るとソースになること（markdown 2 個）。
- 描いた絵: 上の 77 個を headless の GPU で描き（`anti-webui-math` の `examples/math_snapshot.rs`）、Chromium の KaTeX と並べた。RaTeX 付属の描画で見た違い（根号の添字の前の隙間など）のほかに差は見つからなかった。`\tag` も KaTeX と同じく右端に出る。1.8 倍でも線とグリフがにじまない。
- 残り（2026-11-14 の 3 回目）: 単体テスト（群の中と `\allowbreak`、`\nobreak`、`~` での折り返し、群の中の環境の番号と、番号を抜いた後の幅）、`Ui` を通したテスト（エディタの文中の式の `\\` で次の行に移る）。描いた絵で、`\left( \begin{gather}…\end{gather} \right)`、`\color` と `\large` の中の環境の番号が行の右端に出て、括弧が中身の幅に縮むことを確かめた。
- 折り返しと式番号（2026-11-14 の 2 回目）: 単体テスト（`\label`、`\ref`、`\eqref` の取り出し 3 個、折り返す位置と部品の幅と高さ、環境の番号の振り直しと列、参照の位置と色 3 個、文書の通し番号 1 個）、`Ui` を通したテスト（狭い行で長い式が演算子の後で折り返す、番号の右と `leqno` の左、参照を押すとそのラベルが呼ばれる、Markdown で参照を押すと式へ行き、ないラベルはプログラムへ）。描いた絵で、通し番号（`\nonumber` の行は番号なし）、参照の色、長い式の折り返し、`leqno` を確かめた。
- core、math、markdown のテストはすべて通る。clippy の警告なし。

### 速さと大きさ（リリースビルド、電源あり）

数式 1000 個（文中 500、別行 500）の Markdown（103 KB）を、同じ内容を KaTeX で描く Chromium のページと比べた。

| | AntiWebUI | Chromium + KaTeX 0.19.1 |
|---|---|---|
| 最初の絵まで | 46〜49 ms（作る 41〜44、レイアウト 5、ペイント 0.1）。折り返しと番号を入れた後は 50〜51 ms | 約 650 ms（ページの読み込みから 35、KaTeX 180〜235、スタイルとレイアウト 430〜450） |
| 1 画面下へ | 0.57 ms（最悪 0.71）。後は 0.62 ms | ― |
| エディタの最初のレイアウト | 28〜33 ms。後は 30〜44 ms | ― |
| エディタの 1 打鍵 | 0.48 ms（最悪 0.59）。後は 0.55〜0.58 ms（最悪 0.65〜0.76） | ― |

- AntiWebUI の値は `markdown_view` と `markdown_editor` の計測のテスト（`time_a_long_document`、窓なし）、Chromium の値は headless で `performance.now()` から取った。測り方が同じではないが、桁が違う。
- 式を組む時間は、作る時間のうち約 12 ms（中央値 12 µs/式）。残りはフォント一覧の初期化とノードを作る時間である。
- 打鍵が遅くなった分の多くは、文書全体を読むときに式を集めて番号を確かめる手間（最初は 0.16 ms。番号を作らない式を飛ばし、ソースを写さないようにして減らした）。
- バイナリ（`markdown` の例、strip 後）: 数式なし 60.7 MB → あり 63.5 MB（+2.8 MB、フォント 0.5 MB を含む）。

## やっていないこと

- 手での確認。
- 選択した式の中身を選ぶこと。式は 1 つの箱として選ばれ、コピーするとソースになる。これは KaTeX に `copy-tex`（式の一部を選んでもソースをコピーする拡張）を入れたときと同じである。グリフを 1 つずつ選べても、コピーしたものは意味をなさない。
- RaTeX と KaTeX の違い（根号の添字の前の隙間、`\dots` の間隔、`\overbrace` の幅など 0.08〜0.33 em）。RaTeX の組み方の問題なので、直すなら RaTeX に送る。こちらの描画の問題ではない。
- 読み上げで式を MathML として渡すこと。今はソースを呼び名にしている（KaTeX は MathML も出す）。LaTeX から MathML を作るクレート（math-core など）と、読み上げの口（[34](34-accessibility.md)）に式を渡す道が要る。読み上げの橋渡しのクレートができたときに一緒に入れる。
- 番号を振る環境が、分数や添字の中など、ベースラインからずれる所にあるとき。そこでは番号を抜かず、RaTeX のとおり表のすぐ右に置く。
