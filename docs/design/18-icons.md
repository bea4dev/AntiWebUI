# 18. アイコン

Material Symbols のアイコンを、アプリが使った分だけ同梱して表示する。

## API

```rust
use anti_webui_md3e::components::{icon, sized_icon};
use anti_webui_md3e::icons;

icon(icons::HOME);                 // 24 px、周りの文字の色
sized_icon(icons::SETTINGS, 40.0); // 大きさを指定する

// 軸は文字と同じように指定でき、動かせる
icon(icons::FAVORITE)
    .transition(Transition::ms(200).ease_out())
    .dyn_style(move |s| s.font_axis(b"FILL", if liked.get() { 1.0 } else { 0.0 }))
    .on_click(move |_| liked.update(|l| *l = !*l));
```

- 名前は [Google Fonts](https://fonts.google.com/icons) の名前を大文字にしたもの。数字で始まるものは前に `_` を付ける（`_10K`）。別名も使える（`STAR` は `GRADE` と同じ）。
- `icon` は普通の `Div` を返す。`font_axis`、`font_weight`、`text_color`、`on_click` などはそのまま使える。
- `text_size` では大きさを変えない。箱の大きさと合わなくなるので `sized_icon` を使う。

## 同梱の方法

Material Symbols の Outlined は 4004 個のアイコンが入った可変フォントで、10.7 MB ある。Rounded は 15.2 MB、Sharp は 8.9 MB。

困るのはファイルの大きさだけで、起動とメモリには影響しない。フォント全体の登録は 4〜8 µs で、読まれるのは使ったところだけ。

| 方式 | バイナリの増分 | 欠点 |
|---|---|---|
| 丸ごと埋め込む | 常に +7.4 MB（リガチャと名前を除いて） | 1 個しか使わなくても全部入る |
| **1 個ずつ別のフォントにする** | 下の表 | 名前の文字列からは引けない |
| アプリ側で抜き出す | 20 個で 26 KB、100 個で 162 KB | 一覧の管理が要る。漏れは実行時まで分からない |
| 厳選した分だけ同梱する | 300 個なら常に 510 KB | ないアイコンは使えない |

### 1 個ずつ別のフォントにする

`anti-webui-symbols-outlined` クレートは、アイコンごとに 1 グリフのフォント（中央値 2.8 KB）と定数を持つ。

```rust
static S_E9B2: Symbol = Symbol {
    font: include_bytes!("../fonts/e9b2.ttf"),
    family: "material-symbols-outlined-e9b2",
    ch: '\u{e9b2}',
};
pub const HOME: &Symbol = &S_E9B2;
```

使われない `static` はリンカが捨てるので、一覧も集計ツールも要らない。ライブラリの中で使っているアイコンも同じ。Flutter はビルド時にソースを調べてフォントを小さくするが、Rust ではリンカに任せられる。

| 使う数 | バイナリの増分（strip 後） |
|---|---|
| 1 個 | 15.6 KB（うち約 13 KB はコード） |
| 3 個 | 20 KB |
| 20 個 | 66 KB |
| 100 個 | 319 KB |
| 500 個 | 1.65 MB |
| 全部 | 12.9 MB |

基準は `button` だけを使うアプリの 16.0 MB。測ったのは Linux だけ。

定数を `static` への参照にしているのは、同じアイコンを何か所で使ってもフォントを 1 つにするため。定数がフォントそのものを持つと、バイト列は使う場所ごとに複製されることがある（デバッグビルドで確かめた）。アドレスも変わるので、登録済みかどうかを判定できなくなる。

クレートの `rlib` はリリースで 14 MB、デバッグで 29 MB、コンパイルは 0.5 秒。公開するときの圧縮後の大きさは約 5 MiB で、crates.io の上限（10 MiB）に収まる。ほかの字体は別のクレートにする。そのときに `Symbol` は小さなクレートへ移す。

### 文字列で引けないこと

設定ファイルの `"home"` からアイコンを出すには、全部の表が要る。それをクレートに持たせると全員に 12.9 MB かかるので、持たせない。Flutter の `MaterialSymbols.get()` も同じで、使うとアイコンの削減を切る必要がある。必要なアプリは、元のフォントで `Symbol` を自分で作ればよい。

```rust
static HOME: icons::Symbol = icons::Symbol {
    font: include_bytes!("MaterialSymbolsOutlined.ttf"),
    family: "My Symbols",
    ch: '\u{e9b2}',
};
icon(&HOME);
```

`Symbol` の中身は公開なので、自分で小さくしたフォントや、ほかのアイコンフォントも同じように使える。

### 名前で書かないこと

Web のように `"home"` と書くとリガチャでアイコンになる仕組みは使わない。残すと英字とリガチャの表が全部付いて、100 個に抜き出しても 7.5 MB から減らない。定数なら間違いがコンパイルエラーになるし、補完も効く。

## フォントの作り方

`tools/generate.py` が、固定したコミットのフォントから `fonts/` と `src/generated.rs` を作る。出典は `fonts/NOTICE` に書いた。ライセンスは Apache 2.0 で、配布するアプリは `fonts/LICENSE` と `fonts/NOTICE` も一緒に配布する必要がある。

- 4 軸（`FILL`、`GRAD`、`opsz`、`wght`）をすべて残す。全アイコンの大きさは 4 軸で 7.4 MB、`FILL` と `wght` で 2.1 MB、`FILL` だけで 0.95 MB だが、1 個にすると差は数 KB で、削ると失うもののほうが大きい。
- `head` の箱は元のフォント全体のものを残す。ダメージの計算が、軸を動かしたときにグリフがどこまで届くかをここから見積もるため。
- `name` はファミリ名の 1 レコードだけ残す。ないと fontique がフォントと認めない。

## アイコンの箱

| 指定 | 理由 |
|---|---|
| 幅と高さを `size` に固定 | 倍率 1.8 の 24 px は 43.2 px で、文字の幅は 44、行の高さは 43 になる。固定すれば正方形になる |
| `flex_none` | 狭い行でつぶれない |
| 行の高さを 1 倍 | このフォントの上下の値はちょうど em の中心が合うようにできている |
| 中央揃え、太さ 400、字間 0、斜体なし、線なし | 周りの文字の設定をアイコンに持ち込まない |
| `select_none` | 文字として選択されない |

色、`FILL` などの軸は親から継承する。ボタンの文字色やホバーの `GRAD` にそのまま従う。

`opsz` は文字サイズに自動で合うので（[17](17-font-axes.md)）、`sized_icon` の大きさに従う。範囲は 20〜48。24 px は全軸が既定値になり、座標なしのグリフ画像を使う。

## 登録

`icon` が作られたときに、そのアイコンのフォントを 1 度だけ登録する。登録は約 2 µs。

今までの `register_font_as` は、登録のたびに全テキストの整形と全レイアウトをやり直していた。アイコンが後から現れるたびにこれが起きるのを避けるため、次の両方を満たす登録ではやり直さない（[04](04-text.md)）。

- その名前を、どのテキストもまだ求めていない。
- その名前のファミリがまだない。あるならフォールバックなどで使われている可能性がある。

## 確認

- `anti-webui-md3e/tests/icons.rs`: 箱の大きさ、中央に描かれること、色、周りの文字の影響を受けないこと、軸、`opsz`、`FILL` の遷移、選択できないこと、登録、後から現れたアイコンで再レイアウトしないこと、自分のフォント。
- `anti-webui-symbols-outlined/tests/fonts.rs`: 全ファイルのグリフ、軸、`head` の箱、定数と名前の対応。
- `anti-webui-core/tests/fonts.rs`: 登録でやり直すかどうかの条件。

一度だけの確認（リポジトリに入れていない）:

- **元のフォントとの一致:** 4004 個すべてを 8 通りの大きさと軸で、swash のラスタライズ結果を元のフォントのものと比べた。32,032 枚で差はなし。
- **Chrome との一致:** ヘッドレスの Chrome（`--font-render-hinting=none`）と同じ配置で描き、6 アイコン、5 サイズ（20〜48）、5 倍率（1〜2）の 150 通りでインクの箱を比べた。差はすべて 1 px 以内。`check_box_outline_blank` は 25 通りすべてで完全に一致。インクの総量の比は 0.95〜1.06。

## 性能

RTX 5070、ShojiWM、120 Hz、倍率 1.8、900×720。24 px の違うアイコン 100 個（`bench_icons`）。各 2 回。Chrome は全プロセスの合計で、元のフォント（10.7 MB）を読み、`requestAnimationFrame` で `font-variation-settings` を変える。

| `FILL` を動かす数 | AntiWebUI の CPU | Chrome の CPU | AntiWebUI の PSS（無名） | Chrome の PSS（無名） |
|---|---|---|---|---|
| 0 | 0.3〜0.4% | 4.7〜4.9% | 121 MiB（24）※ | 368〜371 MiB（321〜328） |
| 1 | 8.1〜8.7% | 32.4〜37.3% | 123 MiB（25） | 406〜410 MiB（345） |
| 20 | 11.5〜11.6% | 45.9〜49.0% | 123 MiB（25） | 415〜418 MiB（345〜360） |
| 100 | 29.5〜31.2% | 86.1〜87.3% | 124 MiB（26） | 475〜541 MiB（405〜463） |

※ 1 回目は 155 MiB（43）。起動直後の 1 回だけ大きかった。原因は未調査。

- `FILL` の全域を約 1 秒で動かすと、1/64 の丸めで描くのは毎秒約 61 回（[17](17-font-axes.md)）。Chrome は毎フレーム正確な値を描いているはずで、同じ処理量の比較ではない。
- 1 フレームの CPU は p50 が 1 個で 0.8 ms、20 個で 1.1 ms、100 個で 3.4 ms。p95 は 1.0、1.5、4.4 ms。
- 電力は比較できなかった。同じ条件で 7.4 W と 22.6 W になることがあり、差が測定のばらつきに埋もれる。
- 全部を組み直すとき（倍率の変更など）は、違うフォントが多いぶん遅い。100 個で 277 → 377 µs、1000 個で 3.0 → 4.2 ms（1 つのフォントと比べて。各 1 回）。

**未計測:** 内蔵 GPU をコンポジタの出力にした状態と 60 Hz。Windows と macOS のリンカ。

## やっていないこと

- ボタンの中のアイコン（`.icon()` など）。ボタンの部品を増やすときに足す。
- Rounded と Sharp。
- 文字列からの検索。
- 右から左へ書く言語での反転。
- アクセシビリティのラベル（AccessKit を入れるときに足す）。
