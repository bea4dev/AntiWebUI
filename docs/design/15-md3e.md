# 15. anti_webui_md3e（Material 3 Expressive の部品）

Material 3 Expressive（MD3E）の見た目の部品を、別のクレートとして提供する。標準の `button()` などの見た目は変えない。

```rust
use anti_webui::prelude::*;
use anti_webui_md3e::components::{button, loading_indicator, wavy_progress};

div()
    .child(button("保存").on_click(move |_| save()))
    .child(wavy_progress(move || progress.get()))
    .child(loading_indicator())
```

標準のウィジェット（[21](21-widgets.md)）と名前が重なるので、`use anti_webui_md3e::components::*` と `anti_webui::prelude::*` を同時に書くと `button` があいまいになる。部品は名前を挙げて `use` するか、パスで書く。

## 方針

- **公開 API だけで書く。** 依存は `anti-webui` だけにする。内部 API が欲しくなったら、それはコアに足りない機能なので、コアの公開 API に足す。`tests/public_api.rs` が、`anti_webui::prelude`、`anti_webui::widgets`、テスト用の `anti_webui::wgpu::check_shader` 以外を使っていないことを確かめる。
- **動きは標準の部品から借りる。** スイッチ、チェックボックス、ラジオボタン、スライダー、タブ、ツールチップ、ダイアログとシートは、`switch_with` などに見た目だけを渡す（[33](33-customization.md)）。
- **部品は普通の `Div` を返す。** 標準のウィジェットと同じく、`.w(...)` や `.on_click(...)` を続けて書ける。
- **テーマの仕組みをコアに持ち込まない。** 配色はこのクレートの中にシグナルとして持つ（`set_color_scheme`）。

## 値の出どころ

トークンは Jetpack Compose の Material 3 のソース（`androidx-main`、2026-11-03 時点）から取る。Material のウェブ仕様とボタンの角丸が一致することを確認した。

| 内容 | 出どころ |
|---|---|
| 配色 | `tokens/ColorLightTokens.kt`、`ColorDarkTokens.kt`、`PaletteTokens.kt` |
| モーション | `tokens/ExpressiveMotionTokens.kt` |
| 状態レイヤー | `tokens/StateTokens.kt` |
| ボタン | `tokens/Button*Tokens.kt`、`FilledButtonTokens.kt` など |
| 進捗バー | `tokens/LinearProgressIndicatorTokens.kt`、`WavyProgressIndicator.kt` |
| ローディング | `tokens/LoadingIndicatorTokens.kt`、`LoadingIndicator.kt`、`MaterialShapes.kt` |
| 形 | `MaterialShapes.kt`、graphics-shapes の `RoundedPolygon.kt`、`Shapes.kt`、`Cubic.kt`（2026-11-09 時点） |
| リップル | `material-ripple/RippleAnimation.kt` |

## 部品

### ボタン

```rust
button("保存")                     // filled、Small、丸
tonal_button("編集")
elevated_button("共有")
outlined_button("取消")
text_button("詳細")

styled_button("保存", ButtonStyle::filled().size(ButtonSize::Medium).square())
```

| サイズ | 高さ | 左右の余白 | 丸以外の角丸 | 押下時の角丸 |
|---|---|---|---|---|
| ExtraSmall | 32 | 16 | 12 | 8 |
| Small | 40 | 16 | 12 | 8 |
| Medium | 56 | 24 | 16 | 12 |
| Large | 96 | 48 | 28 | 16 |
| ExtraLarge | 136 | 64 | 28 | 16 |

| 種類 | 背景 | ラベル | 通常の影 | ホバーの影 | 枠線 |
|---|---|---|---|---|---|
| filled | primary | onPrimary | なし | Level 1 | なし |
| tonal | secondaryContainer | onSecondaryContainer | なし | Level 1 | なし |
| elevated | surfaceContainerLow | primary | Level 1 | Level 2 | なし |
| outlined | なし | onSurfaceVariant | なし | なし | outlineVariant |
| text | なし | primary | なし | なし | なし |

**押したときの形の変化。** 角丸の半径を `animated` で動かす。Compose は「ボタンは弾ませない」として形の変化に標準の効果（1600、1.0）を使っている（`Button.kt`）ので、同じにする。

**状態レイヤーとリップル。** `overlay` の 1 つのシェーダーで描く。

| 項目 | 値 |
|---|---|
| 状態レイヤー | 色はラベルの色、ホバー 8%、フォーカス 10% |
| リップルの濃さ | 押下 10%。75 ms で現れ、150 ms で消える |
| リップルの半径 | 長辺の 0.3 倍から、対角線の半分 + 10 dp まで 225 ms |
| 同時に出せるリップル | 3 つ。それ以上は最も古いものを置き換える |

Compose と同じく、消えるのは広がり切った後。リップルが無く、状態レイヤーも 0 の間は `overlay` が `None` を返すので、描画は標準の箱と同じになる。

アイコン、トグル、アイコンボタン、FAB、グループは [19](19-buttons.md)、それ以外の部品は [20](20-md3e-components.md)。

**無効。** `ButtonStyle::disabled_when(f)`。背景は onSurface 10%、ラベルは onSurfaceVariant 38%。

**フォーカス。** `secondary` の色で 3 dp のアウトラインを 2 dp 離して描く。

### 波打つ進捗バー

```rust
wavy_progress(move || progress.get())   // 0.0 〜 1.0
```

| 項目 | 値 |
|---|---|
| 大きさ | 既定で 240 × 10 dp |
| 線の太さ | 4 dp |
| 波の振幅 | 3 dp |
| 波長 | 40 dp |
| 波の速さ | 1 秒に 1 波長 |
| 進捗の先と残りの間 | 4 dp |
| 終点の丸 | 直径 4 dp |
| 波が出る範囲 | 進捗 10% 超 95% 未満。それ以外は直線 |
| 進捗の変化 | 500 ms の直線補間 |

波は実際の距離に近い値で塗るので、拡大しても `f.pixel` の分だけアンチエイリアスされる。波の振幅が 0 で進捗も止まっている間は、フレームを要求しない。

### ローディング

```rust
loading_indicator()
```

| 項目 | 値 |
|---|---|
| 容器 | 48 × 48 dp |
| 形の大きさ | 38 dp |
| 形の順番 | SoftBurst → Cookie9Sided → Pentagon → Pill → Sunny → Cookie4Sided → Oval |
| 変形の間隔 | 650 ms |
| 変形のばね | ばね定数 200、減衰比 0.6 |
| 全体の回転 | 4666 ms で 1 周 |
| 変形ごとの回転 | 90 度 |

形は下の「形」の仕組みを使う。7 種類とも箱の中心から輪郭全体が見える形なので、表の中心は箱の中心のまま。以前は `smoothing` を無視し、曲線そのものの範囲で大きさを揃えていた。今は Compose と同じく制御点の範囲で揃えるので、`Cookie4Sided` などが少し小さくなった。

### 形

```rust
use anti_webui_md3e::components::{MaterialShape, ShapeStyle, shape, styled_shape};

shape(move || if open.get() { MaterialShape::Cookie9Sided } else { MaterialShape::Circle })
styled_shape(
    move || MaterialShape::ALL[i.get() % MaterialShape::ALL.len()],
    ShapeStyle::new()
        .color(|c| c.tertiary)              // 既定は primary
        .spring(motion::fast_spatial())     // 既定は標準の移動（380、0.8）
        .rotation(move || i.get() as f32 * 90.0)  // 度。同じばねで回る
        .stroke(2.0),                       // 輪郭の内側に線だけ描く
)
.w(64.0).h(64.0)
```

`MaterialShape` は Compose の `MaterialShapes` のカタログ（`Puffy` を除く 34 種類）。`MaterialShape::ALL` はカタログの順。

- 箱を形で塗る。既定の大きさは 48 × 48。形は Compose の `toShape()` と同じく箱いっぱいに引き伸ばすので、そのままの比で見せたいときは正方形の箱にする。
- `fill` で塗るので `bg` より下になる。箱に `bg` を付けると形が隠れる。子は形の上に描かれ、形では切り抜かない。
- 形が変わると、そのときの見た目から新しい形へばねで移る。途中で変わっても、その時点の形から始まるので跳ばない。回転も `follow` で同じばねを使う。回して箱からはみ出した分は箱で切れる。
- 止まっている間はフレームを要求しない。

**ばね。** Compose に任意の形どうしを変形させる部品はない。`MaterialShapes` を変形させるのはローディングだけで、これは専用のばね（200、0.6）。Expressive の動きの体系では形の変化は「移動（spatial）」で、弾んでよい。大きさを選ばない部品なので、既定は標準の移動（380、0.8）にした。小さい部品には速い移動が合う。ボタンの角丸が標準の効果を使うのは「ボタンは弾ませない」ためで（上の「ボタン」）、飾りとして変形させる形には当てはまらない。

#### 作り方（Compose との違い）

Compose は `RoundedPolygon` を 3 次曲線にして `Morph` で補間する。今回は、形を**内側の 1 点からの距離の表**にして補間する。

1. 頂点と角の丸めから輪郭を作る。`RoundedPolygon` の処理（辺の長さが足りないときの丸めと `smoothing` の分け方、角の 3 本の曲線、`Cubic.circularArc`）をそのまま移した。頂点の座標と丸めは `MaterialShapes.kt` と同じ値。
2. `normalized()` と同じく、制御点も含めた範囲で 1 × 1 に収める。制御点は曲線の外に出ることがあるので、`Circle` の半径は 0.492、`Arrow` は箱の 0.887 になる。Compose でも同じ。
3. 曲線を折れ線にし、表の中心から 256 方向の距離を求める。中心は箱の中心。そこから輪郭全体が見えない形（`PixelTriangle`）は、最もよく見える点を格子から選ぶ。
4. 2 つの形の表と中心を CPU で補間してパラメータとして渡す。シェーダー（`shape.wgsl`）は、表の傾きと箱の引き伸ばしから輪郭までの距離を求め、`f.pixel` の幅でアンチエイリアスする。中心の近くでは傾きからの見積もりが崩れるので、最も近い輪郭までの距離で下から押さえる。

表の形式は、中心から輪郭まで線分が他の輪郭と交わらない形しか表せない。`Puffy` はこぶが少し張り出していて、どの点から見ても交わる（箱の 1.8% の深さ）ので外した。

Compose との差:

- 頂点の対応付けが角度そのものになるので、変形の途中の形は Compose と同じにならない。
- 256 方向の間は直線で補間するので、角の鋭い形（`Burst`、`Boom`、`PixelCircle`、`PixelTriangle`）は、大きく描くと角がわずかに丸まる。
- `Puffy` がない。

## 配色

```rust
set_color_scheme(ColorScheme::dark());
let c = color_scheme();     // シグナルから読むので、切り替えると追従する
```

`ColorScheme::light()` と `dark()` は Compose の既定の配色。`ColorScheme` は公開フィールドの構造体なので、自分で作ってもよい。種の色から配色を作る処理（HCT）は今回は入れない。

## 文字とフォント

ラベルは Roboto Flex（14、weight 500、行の高さ 20、字間 0.1）。

- フォントは `bundled-fonts` フィーチャ（既定で有効）で埋め込み、最初の部品を作るときに登録する。約 1.8 MB。ライセンスは SIL OFL 1.1 で、`fonts/OFL.txt` に同梱している。配布するアプリは、この表記も一緒に配布する必要がある。
- 日本語などは Roboto Flex に無いので、フォールバックでシステムのフォントになる。
- 使う `font_family` は `"Roboto Flex, system-ui, sans-serif"`。
- `opsz` は文字サイズに自動で合う（[17](17-font-axes.md)）。

アイコンは Material Symbols を、使う分だけ同梱する（[18](18-icons.md)）。

## コアに足したもの

このクレートを書く中で足りなかったもの。

| 追加 | 理由 |
|---|---|
| `register_font` | フォントの同梱 |
| `.fill`、`.overlay`、`Shader` | 状態レイヤー、リップル、進捗バー、ローディング |
| `.on_active(bool)` | 押下の開始と終了を知る。ポインタが外に出てから離したときも来る |
| `.on_focus_visible(bool)` | CSS の `:focus-visible`。クリックではフォーカスの表示を出さない |
| 同じ種類のリスナーを複数持てること | `button("x").on_hover(...)` で部品のホバー処理が消えないように |
| `Spring::from_ratio` | Material のトークンは減衰比で書かれている |

## 確認

`anti-webui-md3e/tests/components.rs` は `anti_webui` の公開 API だけを使い、大きさと色、押したときの形とリップル、無効、キーボード操作、配色の切り替え、フォント、進捗バーとローディングの描画を確かめる。止まっているボタンがフレームを要求しないことも確かめる。

形の表は、すべての形で、表の中心からの 1024 方向がどれも輪郭と 1 回だけ交わること、表が輪郭の位置と一致すること、形が箱に収まることをユニットテスト（`src/shapes.rs`）で確かめる。`Puffy` はこのテストを通らない。`tests/shapes.rs` は、全部の形が箱の中心を塗り、どの 2 つも違って見えること、端数のスケールで輪郭がアンチエイリアスされること、変形がフレームごとに進んで最後に最初からその形だったものと同じ絵になり、その後フレームを要求しないこと、途中で変えても跳ばないこと、回転、線、`Ink` を確かめる。

ショーケースの `communication` に全部の形を並べ、オフスクリーンの絵を目で確かめた。Compose の実物との画面比較はしていない。

作者が実機で `gallery` を動かして問題ないことを確かめた。Compose の実物との画面比較はしていない。

## 性能

2026-11-03。[14](14-shaders.md) と同じ環境（RTX 5070 Laptop、ShojiWM、120 Hz、スケール 1.8）で、窓は 900×720。`bench_md3e` と、同じ動きを `requestAnimationFrame` と SVG の `path` で書いたページを Chrome で比べた。起動後 4 秒を除いた 8 秒、各 2 回。CPU は 1 コアを 100% とし、Chrome は全プロセス（11 個）の合計。

| 負荷 | AntiWebUI CPU | Chrome CPU |
|---|---|---|
| 何も動かない（ボタン 30 個 / ボタン 1 個のページ） | 0.0〜0.1% | 0.2% |
| ローディング 1 個 | 4.2〜4.7% | 24.3〜26.7% |
| 進捗バー 1 本 | 3.6〜4.2% | 22.1〜22.2% |
| ローディング 20 個 | 4.7〜6.2% | 26.3〜27.8% |
| 進捗バー 20 本 | 5.0〜6.4% | 24.4〜24.5% |
| 参考: Chrome の CSS `transform` の回転（合成だけ） | | 12.1〜13.5% |

- どちらも約 120fps。
- コンポジタの CPU（AntiWebUI で 22〜30%、Chrome で 22〜24%）と NVIDIA の電力（どちらも約 22 W。何も動かないときは 8.7 W）は、動かす内容が変わってもほとんど変わらない。変更範囲が 0.0% でも 95.8% でも同じなので、部品の違いは電力の差として見えない。
- Chrome のページは比較用に書いたもので、形の計算は同じ大きさの表だが同じ形ではない。Compose の実物ではない。

メモリ（10 秒後。`smaps_rollup`）:

| | RSS | PSS | 無名 |
|---|---|---|---|
| AntiWebUI + ローディング 1 個（NVIDIA） | 247 MiB | 125 MiB | 24 MiB |
| AntiWebUI + ローディング 1 個（Radeon 880M） | 113 MiB | 60 MiB | 10 MiB |
| md3e なしの `bench_pacing`（NVIDIA / Radeon 880M） | 246 / 112 MiB | 124 / 59 MiB | 23 / 9 MiB |
| Chrome（11 プロセス） | 1332 MiB | 354 MiB | 250 MiB |

RSS の多くはドライバと共有ライブラリのマップ。md3e が増やす無名メモリは約 0.5 MiB。

動かし続けたときの無名メモリを、15 秒後と 135 秒後で比べた。Radeon 880M では 10.0 → 10.2 MiB。NVIDIA では 0.6〜2.1 MiB 増えるが、シェーダーを使わない `bench_pacing` と `bg` だけの負荷でも増えるので、シェーダーだけの問題ではない。原因は未調査。

Radeon 880M の行は、コンポジタが NVIDIA のまま、アプリだけを `VK_LOADER_DRIVERS_SELECT` で Radeon にしたもの。

押したとき（ボタン 30 個のページ、オフスクリーン）: シェーダーをプリロードしているので、最初の押下のフレームも描画時間は止まっているときと同じ（NVIDIA 約 2.3 ms、Radeon 約 1.4 ms。読み戻しを含む）。UI の処理は p50 約 0.02 ms、最大 0.16 ms。

**未計測:** 内蔵 GPU をコンポジタの出力にした状態と 60 Hz。実ウィンドウでのリップル（経路はローディングと同じなので、同程度と見ている）。

## やっていないこと

- HCT による配色の生成。
- 子を形で切り抜くこと（[14](14-shaders.md) の `aw_shape_distance` を入口にして後から足す）。`Ink` の状態レイヤーも箱の角丸で描き、`MaterialShape` の形にはならない。
- `Puffy`（上の「形」）。距離場をテクスチャにする方式にすれば表せる。部品の API は変わらない。
