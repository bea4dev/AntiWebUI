# 13. アニメーション API

`request_frame` だけで書くと、途中からの切り返し、要素が消えたときの停止、イージングを毎回自分で書くことになる。これらをフレームワークが引き受ける API を 2 つ用意する。

| | 向いている場面 | 動かすもの |
|---|---|---|
| `transition` | スタイルが変わるときに、なめらかにつなぎたい | フレームワークが途中の値を計算する |
| `animated` | クリックやドラッグの結果など、値を自分で動かしたい | シグナルのように読める値 |

## `transition`

```rust
div()
    .bg(WHITE)
    .hover(|s| s.bg(BLUE).scale(1.05))
    .transition(Transition::ms(150).ease_out())

// 対象を絞る
div().transition_of([Prop::Scale, Prop::Opacity], Transition::ms(200).ease_in_out())
```

- `hover`、`focused`、`active`、`dyn_style`、どれで値が変わっても動く。
- CSS と同じく、**変更後のスタイル**に書かれた `transition` を使う。`hover(|s| s.scale(1.1).transition(速い))` と書くと、入るときだけ速くできる。
- 継承しない。

### 対象

| `Prop` | プロパティ | コスト |
|---|---|---|
| `Translate`, `Scale`, `Rotate`, `Opacity`（変形のあるノード） | 変形と不透明度 | 合成だけ（[12](12-transform.md)） |
| `Opacity`（変形のないノード）, `Background`, `BorderColor`, `OutlineColor`, `TextColor`, `Radius`, `Shadow` | 色、角丸、影 | 描き直し |
| `Width`, `Height`, `Margin`, `Padding`, `Inset`, `Gap`, `BorderWidth` | 大きさと位置 | レイアウト |

`Length` は `Px` 同士、`Percent` 同士だけつなぐ。`Auto` が絡むとすぐ切り替わる（CSS と同じ）。影は同じ順の同士をつなぎ、数が違うときは足りない分を透明な同じ影とみなす。内側と外側が違うとすぐ切り替わる。

色はプリマルチプライドで補間する。`TRANSPARENT` から青へ変えても途中で黒ずまない。

### 動かない場合

- 作られたばかりのノード、`display: none` だったノード、`display: none` の中のノード。変化の前の見た目が無いので、最終の値から始まる。
- `Transition::ms(0)`、または対象に入っていないプロパティ。

### 途中で変わったとき

- 今の値から、新しい目標へつなぐ。
- 元の値へ戻るとき（ホバーして、すぐ離れたとき）は、CSS の reversing shortening と同じく、それまで進んだ割合だけ時間を縮める。少し動いただけなのに戻りに全部の時間が掛かると、のろく感じるため。
- 新しいスタイルに `transition` が無ければ、すぐ最終の値になる。

### 実装（core）

`resolve_node` で、スタイルの層を重ねた結果（目標）を計算した後に次を行う。

1. 動いているプロパティ: 目標が変わっていれば、つなぎ直す。変わらなければ、今の値で上書きする。
2. 動いていないプロパティ: 前回の結果と違い、`transition` があれば、動かし始める。
3. 終わったものは、目標の値にして取り除く（ここで次のアニメーションを始めないよう、終わる印を付けて `resolve_node` で取り除く）。

`Ui::animate` は動いているノードの今の値を更新し、`mark_style_of` を呼ぶだけで、あとは通常の経路（スタイル → レイアウト → ペイント）を通る。これにより:

- 変形だけが動くなら、[12](12-transform.md) の経路で内容を描き直さない。
- 色の継承、レイアウトの無効化、差分がそのまま効く。
- ノードが消えれば、動いていた情報も一緒に消える（`Node` が持つ）。

`dyn_style` は目標が変わったときに 1 回呼ばれるだけで、毎フレームは呼ばれない。

開始時刻は `resolve_node` を通った時の `Instant::now()`。次のフレームの `now` との差から始まるので、最初の 1 フレームを無駄にしない。

## `animated`

```rust
let x = animated(0.0_f32);

div()
    .dyn_style(move |s| s.translate_x(x.get()))
    .on_click(move |_| x.to(300.0, Transition::ms(300).ease_out()));

x.spring_to(300.0, Spring::default());
x.set(0.0);   // すぐ変える
x.stop();     // 今の値で止める
```

- `Signal` と同じく `Copy` で、`get` は依存関係を登録する。`dyn_style` は動いている間だけ毎フレーム呼ばれる。
- `T` は `f32`、`(f32, f32)`、`Color`（`Animatable` を実装すれば増やせる）。
- 所有者が破棄されると止まる（`request_frame` を手で使うときのような panic は起きない）。
- 動いている途中で `to` や `spring_to` を呼ぶと、今の値からつなぐ。`spring_to` は速度も引き継ぐ。

### Spring

```rust
Spring { stiffness: 170.0, damping: 26.0, mass: 1.0 }   // 既定（react-spring の default 相当）
```

時間ではなくバネの性質で指定する。途中で目標が変わっても動きが途切れない。

- 1 ms ごとの固定ステップで積分する。フレームの間隔に関わらず同じ動きになる。
- 動いた距離の 0.05% 以内に入り、速度も小さくなったら止まる。

### フレームごとの処理

`request_frame` のコールバックはまとめて `batch` の中で実行する。複数の `animated` を読む `dyn_style` でも 1 フレームに 1 回しか呼ばれない。

## `enter` / `exit`

```rust
show(move || open.get(), view)
    .enter(|s| s.opacity(0.0).scale(0.95))
    .exit(|s| s.opacity(0.0).scale(0.95))
    .transition(Transition::ms(150).ease_out())
```

- `enter`: 作られたとき、この値から今のスタイルへ動く。
- `exit`: `when` が偽になったとき、この値へ動き、終わったら破棄する。片方だけでもよい。
- `transition`: 省略すると `Transition::ms(150).ease_out()`。ノード自身の `.transition` より優先するのは、出入りの間だけ。
- `appear()`: 最初から `when` が真のときも `enter` を動かす。

`enter` も `exit` も無い `show` は今までと同じ経路を通り、コストは増えない。

### 振る舞い

| 場面 | 振る舞い | 理由 |
|---|---|---|
| 最初から `when` が真 | `enter` は動かない（`appear()` で動く） | 画面を開いたときに全部が動き出さないように（Vue の `appear`、Svelte の `intro` と同じ既定） |
| `exit` の途中で `when` が真に戻る | **同じノード**のまま戻る。入力中の文字やスクロール位置は残る | 作り直すと一瞬ちらつき、状態も失う |
| `enter` の途中で `when` が偽になる | 今の値から `exit` へ。`exit` が `enter` と同じなら、進んだ分の時間で戻る | [途中で変わったとき](#途中で変わったとき)と同じ |
| `exit` の途中 | ポインタは素通りする（`pointer_events: false`）。中にフォーカスがあれば外す | 消えていく閉じるボタンを押せたり、見えないものに文字が入ったりしないように |
| `exit` の途中で親が消える | 待たずに一緒に消える | |
| 非表示の中 | 待たずに消える | 見えない動きを待つ意味が無い |

### 対象のノード

`view` の一番外の箱に掛かる。フラグメントと `popup` は箱を持たないので、その子に掛かる。

```rust
show(move || open.get(), || popup().child(card()))
    .enter(|s| s.opacity(0.0).translate_y(-4.0))
    .exit(|s| s.opacity(0.0))
```

ポップアップのサーフェスは `exit` が終わるまで閉じない。ただし:

- コンポジタが先に閉じたとき（`xdg_popup` の外をクリック）は、サーフェスが無くなるので `exit` は見えない。アプリから閉じたとき（メニューの項目を選んだときなど）は見える。
- サーフェスは箱に合わせた大きさなので、そこからはみ出す動きは切れる。

### 実装

- `enter` は CSS の `@starting-style` と同じ考え方で実装する。最初のスタイル解決で「変更前のスタイル」を `今のスタイル + enter` とみなすだけで、あとは `transition` と同じ。開始の 1 フレームを待たない。
- `exit` は `Node::presence` に持ち、`resolve_node` がホバーなどの層の上に重ねる。
- `when` が偽になったら、対象のノードの動きが終わるのを `request_frame` で待ってから、中身の `Owner` を破棄する。破棄を遅らせるだけなので、中の `signal` や `animated` は最後まで生きている。
- 中身の `Owner` は `show` の外側の `Owner` に属する（`for_each` と同じ）。`show` の effect が再実行されても破棄されず、親が消えれば一緒に消える。

## `for_each` の `enter` / `exit`

```rust
for_each(move || items.get(), |t| t.id, |t| row(t))
    .enter(|s| s.opacity(0.0).translate_y(-8.0))
    .exit(|s| s.opacity(0.0).translate_x(20.0))
    .transition(Transition::ms(150).ease_out())
```

`show` と同じメソッドを持ち、項目ごとに `show` と同じことが起きる。対象のノード、`exit` の間の入力の扱い、`appear()` も同じ。`enter` も `exit` も無ければ今までと同じで、コストも増えない。

### 消える項目の場所

**消える項目は、直前にあった項目の後ろに残る。** 残っている間は場所を取る。先頭にあった項目は先頭に残る。

```
表示     [A, x, B, y, C]    x と y を消して N を足す
新しい値 [C, N, A, B]
表示     [C, N, A, x, B, y]   A の後ろに x、B の後ろに y
```

続けて消える項目は順番のまま同じ項目の後ろに並ぶ。React の TransitionGroup と Vue の TransitionGroup も、消える項目を並びの中に残す（残す基準が直前か直後かだけが違う）。直前を基準にしたのは、末尾に項目を足しても、消えている途中の項目がその後ろへ回らないため。

### 振る舞い

| 場面 | 振る舞い |
|---|---|
| 最初からある項目 | `enter` は動かない（`appear()` で動く） |
| 項目が増えた | `enter` から動く |
| 項目が減った | `exit` へ動き、終わったら破棄する。`exit` が無ければすぐ破棄する |
| `exit` の途中で同じキーが戻る | **同じノード**のまま、今の値から戻る。場所は新しい値に従う |
| `exit` の途中で値がまた変わる | 消えている項目は場所のルールに従って並び直し、動きは途切れない |
| `exit` の途中で親が消える | 待たずに一緒に消える |
| 同じキーの項目が残る | 今までどおりノードを使い回す。`view` は呼ばない |

### 周りの項目の動き

消える項目は終わるまで場所を取るので、**終わった瞬間に後ろの項目が詰まる**。詰まる動きもなめらかにしたいときは、`exit` で高さも動かす。

```rust
for_each(items, key, |t| row(t).h(32.0).overflow_hidden())
    .enter(|s| s.opacity(0.0).h(0.0))
    .exit(|s| s.opacity(0.0).h(0.0))
```

- 動かせるのは `h` が `Px` のときだけ（[対象](#対象)のとおり `Auto` はつながらない）。
- 項目の間隔を親の `gap` で取っていると、高さが 0 になっても `gap` が残り、最後にその分だけ詰まる。詰まる動きが要るときは項目の `mb` で間隔を取り、`exit` で `mb(0.0)` にする。

一覧をまるごと入れ替えると、古い項目が先頭に残るので、その間は新しい項目が下に押し出される。

### 実装

- 消える項目が無い間、並びの計算は今までと同じ。消える項目があるときだけ、前回の並びを 1 回なぞって場所を決める（項目数に比例）。
- 終わりを待つ `request_frame` は 1 つの `for_each` につき 1 つで、毎フレーム見るのは消えている項目だけ。項目数が多くても、消えていなければ何も増えない。
- 消える項目が終わるたびに子の配列から 1 つずつ外すと、同時に k 個消えるときに項目数 n に対して O(nk) になる。先に子の配列を 1 回で作り直してから破棄し、O(n) にする。`enter` / `exit` の無い経路も同じ順にする。
- `Node::presence` は `enter` の開始と `exit` の間だけ持つ。動き終わった項目のスタイル解決には余分なコストが掛からない。
- `show` の中に `for_each` があり、その中に `show` がある、のように同じノードに複数の出入りが掛かるときは、今まさに消そうとしている側の `exit` を使う。

## リアクティブの計算量

アニメーションでは多くの effect が毎フレーム同時に動くので、2 つ直した。

- `flush` は次の effect を探すのに待ち行列全体を見ていた。深さと順番のヒープにした。
- 再実行のたびに依存を全部外して登録し直し、シグナル側の配列も毎回探していた。前回と同じ順に読んでいる間は何もしないようにした。読まなくなったものだけを最後に外す。

| 同時に動く effect | 修正前 | 修正後 |
|---|---|---|
| 10 | 約 1 µs | 0.5 µs |
| 100 | 約 50 µs | 5.6 µs |
| 1000 | 約 4.5〜5.1 ms | 約 64 µs |
| 5000 | 約 112 ms | 約 0.35 ms |

## 計測

同時に動く数ごとの CPU の時間（1 フレーム、animate + update + paint、1620×1616、リリースビルド、ms）。

| 動かし方 | 100 個 | 1000 個 |
|---|---|---|
| `transition`（不透明度） | 0.04〜0.06 | 0.40〜0.47 |
| `transition`（`translate`） | 0.06〜0.08 | 0.72〜0.78 |
| 要素ごとの `animated` | 0.04 | 0.43〜0.49 |
| 1 つの `animated` を全要素で読む | 0.05〜0.08 | 0.59〜0.66 |

1000 個が同時に動いても 120 Hz の 1 フレーム（8.33 ms）の 1 割に届かない。GPU の時間は含まない。

実機（ShojiWM、120 Hz、RTX 5070）で、`transition`、`animated`、`Spring` のカードを同時に繰り返し動かすと、4 秒で 471〜475 フレームだった。

影つきのパネル（400×300、文字あり）を `enter` / `exit` で 0.4 秒ごとに開閉すると、1 フレームの CPU は中央値 0.53〜0.79 ms、GPU は 0.40〜0.61 ms だった（4 秒で 338〜341 フレーム。動いていない待ち時間は描かないので 480 より少ない）。

`for_each` の `enter` / `exit` で、一部の項目が消えているときの CPU の時間（800×600、リリースビルド、ms、中央値）。

| 項目数 | 消える数 | 値が変わったとき | 動いている間の 1 フレーム | 消え終わるフレーム |
|---|---|---|---|---|
| 100 | 1 | 0.02 | 0.02 | 0.04 |
| 2000 | 1 | 0.24 | 0.02 | 0.27 |
| 10000 | 1 | 1.9 | 0.02 | 3.4 |
| 2000 | 100 | 0.60 | 0.06 | 0.73 |
| 10000 | 1000 | 6.0 | 0.54 | 11.6 |

動いている間は項目数によらず、消えている数で決まる。消え終わるフレームは項目を取り除いてレイアウトし直す時間で、`enter` / `exit` の無い `for_each` で同じ数を一度に消すときとほぼ同じ（10000 項目で 1 個: 3.5〜4.1 ms、1000 個: 7.7〜8.8 ms）。

`enter` / `exit` の無い `for_each` は、変更前と比べて並べ替えと構築は同じで、全部を消すときだけ速くなった（10000 項目: 43 → 31 ms、40000 項目: 437 → 254 ms）。

実機（ShojiWM、120 Hz、RTX 5070）で、影つきの項目 6 個を 0.4 秒ごとに足したり消したり並べ替えたりすると（高さも動かす）、1 フレームの CPU は中央値 0.33 ms、GPU は 0.14 ms だった。

## やっていないこと

- `for_each` で残る項目の位置の動き（Vue の `move`、framer-motion の `layout`）。今は詰まる先へすぐ移る。
- `Auto` の高さからの動き（CSS の `interpolate-size`）。
- キーフレーム、ループ、遅延。`animated` と `request_frame` で書ける。
- `transition` での `Spring`。
- `prefers-reduced-motion` に当たる設定。
