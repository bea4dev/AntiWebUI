# 28. Markdown

Markdown のビュワーと、Obsidian のライブプレビューのように書けるエディタ。Mermaid の図も描く。目標は最速・最軽量で、同じ文書を Chromium で開いたときと速さとメモリを比べる。

Web で Markdown エディタを作るときと同じく、基礎の部品を core に置き、それを組み合わせて Markdown の部品を作る。基礎の部品は Markdown 以外（チャット欄、コードエディタ、カスタム絵文字の入力欄）にも使える。

## 構成

| 置き場所 | もの |
|---|---|
| `anti-webui-core` | `rich_text`（`span`、`inline`）、`text_editor`（行ごとの整形、装飾、見えている行だけの整形） |
| `anti-webui-markdown` | `markdown_view`、`markdown_editor`、Mermaid（feature `mermaid`） |

パーサ（`pulldown-cmark`）と Mermaid は `anti-webui-markdown` だけが持ち、core には入らない。

## 段階

| 段階 | 中身 |
|---|---|
| M1 | core: `rich_text` |
| M2 | markdown: `markdown_view`（CommonMark と GFM）、Mermaid |
| M3 | core: `text_editor`（作った。2026-11-06） |
| M4 | markdown: `markdown_editor`（ライブプレビュー。作った。2026-11-06） |

ソースをそのまま書くモード（Markdown 用のコードエディタ）は、コードエディタ（[31](31-code-editor.md)）として別に作り、左にソースと右にプレビューの `markdown_split_editor`（[32](32-markdown-split.md)）の左側に使った。

## M1: `rich_text`

1 つの段落の中で文字のスタイルを変えたり、文字の間に画像などのノードを置いたりする。HTML の `<p>` の中の `<strong>`、`<code>`、`<a>`、`<img>` に当たる。

```rust
rich_text((
    "これは ",
    span("太字").bold(),
    " と ",
    span("code").font_family("monospace").bg(code_bg).rounded(4.0).px(3.0),
    " と ",
    inline(img("party.png").w(20.0).h(20.0)).alt(":party:"),
    " と ",
    span("リンク").text_color(link).hover(|s| s.underline()).on_click(|| open(url)),
))
.text_size(16.0)
```

`span` は `Styled` を持つので、`div` と同じメソッド（`bold`、`italic`、`text_color`、`text_size`、`bg`、`rounded`、`px`、`underline`、`cursor` など）が使える。テーマのように多くの `span` が同じスタイルを使うときは、`shared_style(Rc<Style>)` で 1 つのスタイルを共有できる。`vertical_align(VerticalAlign::Super)` で上付きにする。

### 持ち方

- 段落全体が今までと同じ 1 つのテキストノード（`NodeKind::Text`）である。そのため、文書全体の選択、ダブルクリック、コピー、文字を運ぶ操作がそのまま効く。
- `span` はノードにしない。ノードはスタイルの計算結果などを持っていて重いので、範囲とスタイルの差分だけを `TextData` の `rich` に持つ。`rich` は普通のテキストでは `None` なので、普通のテキストは重くならない。
- `span` は重ならず、並んでいるだけである（入れ子にしない）。入れ子にしたいもの（`**太字の _斜体_**`）は、作る側が重ねたスタイルを持つ `span` に分ける。
- `span` が変えられるのは、文字に関するものだけである。
  - 整形が変わるもの: `font_family`、`font_size`、`font_weight`、`font_style`、`letter_spacing`
  - 描くときだけのもの: `color`、`bg`、`rounded`、`underline`、`strikethrough`
- 左右の余白（`px`、`pl`、`pr`）だけは整形にかかわる。`span` の両端に高さ 0 のインラインボックスを置いて空けるので、CSS の `padding-inline` と同じく、背景の内側に余白ができる。
- `line_height` が倍率のときは、CSS と同じく `span` の文字サイズに対する倍率になる。大きい `span` があると、その行が高くなる。
- `span` のスタイルは、ノードのスタイルが決まるとき（`resolve_styles`）に、ノードのスタイルから受け継ぐものと合わせて解決し、持っておく。整形が変わらない変更（色など）では整形し直さない。
- 整形のキャッシュの鍵には、文字列の版に加えて、インラインボックスの大きさを入れる。

### 背景

背景は、`span` の文字の範囲を行ごとに求め、縦はフォントの ascent から descent までとする。CSS のインライン要素の背景と同じく、`line-height` を大きくしても背景は高くならない。行をまたぐ `span` は、行ごとに別の箱になる（`box-decoration-break: slice` の角は付けず、それぞれ角を丸める）。

### インラインボックス

- `inline(view)` の中身は parley の `InlineBox` として行に流し込む。文字列に代わりの文字は入れず、位置（バイト）だけを持つ。
- 中身は、段落が使える幅の中で max-content の大きさを測ってから整形する。行の中での位置が決まったら、中身をその位置に置く。中身はテキストノードの子なので、描画、当たり判定、画像の読み込みは普通のノードと同じである。
- 縦の位置は `VerticalAlign`（`Baseline`（既定）、`Middle`、`Top`、`Bottom`、`TextTop`、`TextBottom`）で決める。
- コピーしたときは、選択範囲に含まれるインラインボックスの `alt` を、その位置に入れる。

### リンクとホバー

- `on_click` を持つ `span` は、押して同じ `span` の上で離したときに呼ばれる。
- `span` の `cursor` は、その `span` の上にいる間のカーソルになる。`on_click` があるときの既定は `Pointer` である。
- `hover` で変えられるのは描くときだけのスタイルで、整形はやり直さない。

### 入れないもの

- `span` の入れ子、`span` ごとのシグナル（段落全体を `dyn_view` で作り直す）
- 選択範囲がインラインボックスの中身（画像の中のテキストなど）をまたぐときの正しい順番

## M2: `markdown_view`

```rust
markdown_view(source)                     // &str / String / Signal<String>
    .theme(MarkdownTheme::default())
    .on_link(|url| open(url))
    .image(|src| resolve(src))            // 相対パスの解決
    .emoji(|name| custom_emoji(name))     // ":party:" → Option<ImageSource>
    .highlight(|lang, code| spans)        // コードの色分け（`code` feature では既定で tree-sitter。[32](32-markdown-split.md)）
```

- パーサは `pulldown-cmark`。速く、要素ごとにソースのバイト位置を返す。GFM の表、タスクリスト、取り消し線、脚注を有効にする。
- 解析した結果を軽いブロックの列にし、それを普通のノードにする。
  - 見出しと段落は `rich_text`
  - リストは flex
  - 表は grid
  - 引用は左に線のある箱
  - コードブロックは `rich_text`
  - 区切り線は高さのある箱
- テーマは要素ごとの `Style` で、CSS で書くときと同じ感覚で当てられる。既定のテーマは GitHub の見た目に近づける。
- 終わったタスク（`- [x]`）の文字は `task_done` のスタイルで、既定は空（GitHub と同じくチェックが付くだけ）。Obsidian や Notion のように取り消し線と薄い色にするなら、`task_done` に `strikethrough()` と色を入れる。ビュワーとエディタの両方が使う。
- ソースが変わったときは、ブロックごとにソースの文字列を比べ、変わったブロックだけを作り直す。
- コードの色分けは関数を渡すだけにする。`code` feature（既定で有効）では、渡さなければ `anti-webui-code` の `CodeHighlighter`（tree-sitter）で色分けする（[32](32-markdown-split.md)）。

### 表

core にはまだ表のレイアウトがないので、表を列の並びとして作る。列は一番広いセルの幅になる。セルの中は折り返さず、表が広すぎるときは横にスクロールする（GitHub と同じ）。

`code` のように別のフォントの部分があると、行が少し高くなることがある。そのため、各セルの大きさを `on_resized` で受け取り、同じ行のセルの高さを一番高いセルに揃える。揃えるのは描く前なので、ずれた絵は出ない。

### HTML

ブラウザがないので、HTML のブロックは、文字、画像（`<img src alt>`）、リンク（`<a href>`）、改行だけを出す。README によくある `<p align="center">` は中央に寄せる。

### Mermaid

- 言語が `mermaid` のコードブロックを図にする。`merman` で SVG の文字列にし、`svg::parse` でノードにする。
- 図を作るのは 1 本のワーカースレッド（`markdown-diagrams`）で、出来たものはソースのハッシュで 64 個まで覚えておく。作っている間は空の箱を出しておく。
- feature `mermaid`（既定で有効）で外せる。
- `merman` は alpha 版で API がよく変わるので、`=0.10.0-alpha.1` に固定している。上げるときは `src/mermaid/merman.rs` と、下の比較を見直す。

#### クレートの選択

7 つのクレートを比べた（38 個のノードのフローチャートと、シーケンス図。リリースビルド）。

| クレート | 依存 | バイナリ | フローチャート | 文字幅を測る口 |
|---|---|---|---|---|
| `merman` | 122 | +25.2 MB | 2.7 ms | あり（クロージャ、トレイト） |
| `ariel-rs` | 19 | +2.5 MB | 2.8 ms | `fidelity` feature の `set_measurer` |
| `mermaid-rs-renderer` | 33 | +5.2 MB | 184 ms | なし（システムのフォントを読む） |
| mermaid-little | 46 | +8 MB | 34.5 ms | C の関数のコールバック |

最初は軽さを優先して `ariel-rs` を選んだ。その後、「最軽量」は Chromium より軽いことと決まったので、`ariel-rs` と `merman` を、Chromium で描いた mermaid.js 12.3 と比べ直した（2026-11-06）。図は 9 種類 11 個（フローチャート 2、シーケンス 2、クラス、状態、ER、ガント、円グラフ、マインドマップ、Git）。見た目が mermaid.js にずっと近く、それでも Chromium よりはるかに軽い `merman` に切り替え、`ariel-rs` は外した。

| | Chromium（mermaid.js 12.3） | `merman` | `ariel-rs` |
|---|---|---|---|
| バイナリ（strip 後、デモ全体） | 329 MB（本体） | 44.9 MB | 21.9 MB |
| メモリ（PSS、全プロセス、図なし → 11 個） | 530 → 665 MB | 64 → 133 MB | 62 → 105 MB |
| 11 個を描く時間（作る + ノードにして描く。バッテリー駆動） | 1 回目 877 ms、2 回目から約 390 ms | 1 回目 50 ms、2 回目から 43 ms | 1 回目 19 ms、2 回目から 15 ms |

時間はバッテリー駆動で続けて測った比で、電源につないで測り直すと絶対値は変わる（`ariel-rs` は電源につないだときの約 85 %）。

見た目（mermaid.js 12.3 と並べて目で比べた）:

| 図 | `merman` | `ariel-rs` |
|---|---|---|
| フローチャート | ほぼ同じ（大きさ、テーマ、配置）。線の曲げ方が違う。幅 120 をわずかに超えるラベルは 2 行になる（Chromium は折り返さず、箱の端で切れる。箱の大きさは同じ） | mermaid 11 のクラシックのテーマ。小さめ |
| シーケンス | ほぼ同じ | クラシック |
| クラス | 配置は同じ（矢じりと太字は下の修正で同じになった） | クラシック |
| 状態 | 配置が少し違う | 配置が違う |
| ER | ほぼ同じ | クラシック |
| ガント | ほぼ同じ | とても小さく読めない |
| 円グラフ | 同じ | 同じ |
| マインドマップ | 同じ（`layout-cytoscape`） | 配置が違う |
| Git | コミット名が回転しない（両方とも。`svg::text` が回転しないため） | 同じ |

比べる中で直した core の不具合:

- `width="100%"` の `<svg>` を、`max-width` までの幅にし、高さを縦横比から決める（ブラウザと同じ）。前は高さが元のままで、幅だけ縮んで上下に余白ができていた。
- ぼかしのない `feDropShadow`（mermaid 12 の箱の影）を、同じ形を影の色でずらして描く。前は図全体を 1 枚の絵にしていた。
- 図全体を 1 枚の絵にするときに、取り出した文字を絵からも消す。前は文字が二重になっていた。
- 隙間がすべて 0 の破線（Mermaid の線の `0 0 65 0`）を実線として描き、端が平らなときは長さ 0 の線を捨てる（`anti-webui-wgpu` の `dashes_to_stroke`）。kurbo に渡すと輪郭が壊れて黒い箱になっていた。
- 属性の始まり、終わり、中身で選ぶセレクタ（`[id$="-extensionEnd"]` など、`^=`、`$=`、`*=`）を、ファイルの中でそれに当たる値ごとの `[id="…"]` に書き換えてから `usvg` に渡す。`usvg` のスタイルシート（simplecss）はこれを知らず、並んだセレクタごと規則を捨てるので、クラス図の継承の矢じりが白抜きにならなかった。
- HTML のラベルの `font-weight: bolder` と `lighter` を、CSS の表どおり受け継いだ太さから決める。クラス名が太字にならなかった。

残っている違い: Git のコミット名が回転しない。`svg::text` は、まわりの変形の回転を無視して、点の位置だけを移す。回すには、変形のレイヤー（[12](12-transform.md)）を使うことになる。

#### 文字幅

`merman` の `DeterministicTextMeasurer` に、幅を測るクロージャ（`with_width_callback`）を渡し、ワーカースレッドでも core の `svg::measure_text` で測る。フォントの指定（`"Recursive Variable",arial,sans-serif` など）、太さ、斜体は `merman` の `TextStyle` から取る。ワーカースレッドは自分のテキストシステムを持つ（初めの 1 回だけ約 15 ms かかる）。

#### SVG の文字

今までの `svg::parse` は、`<text>` を `usvg` に組ませるために、そのたびにシステムのフォントを全部読み込んでいた（`svg-text` feature）。Mermaid の `<text>` は、ほとんどが点に置く 1 行の文字（`tspan` の入れ子と `x`、`y`、`dy` を含む）だけなので、foreignObject のラベルと同じく、取り出して目印の矩形に置き換え、`svg::text` として描くようにした。位置と変換は `usvg` が解いた目印から取る。1 行の中で文字ごとに位置を変えるもの、パスに沿うもの、途中でスタイルが変わるものは、今までどおり `usvg` に任せる。システムのフォントを読むのは、そういう `<text>` が残るときだけになる。

## M3: `text_editor`

ライブプレビューと、後で作るコードエディタの土台になる。大きな文書でも 1 打鍵が軽いことを最優先にする。CodeMirror 6 と同じく、1 行を 1 つの箱にし、装飾（隠す、置き換える、スタイルを付ける）を外から渡す。

```rust
let editor = editor_ref();
text_editor()
    .value(source)                         // Signal<String> と双方向
    .on_change(|text| save(text))
    .editor_ref(editor)                    // editor.replace(range, "[x]")、editor.select(a, b)
    .decorate(|cx: &DecorateContext| rows) // 行ごとの見た目。なければ素の文字
    .style(...)                            // 箱、文字、スクロール（overflow_y_scroll）は普通の div と同じ
```

### 持ち方

| もの | 中身 |
|---|---|
| 箱（`NodeKind::Editor`） | フォーカスを受ける。文字列、行頭の位置の表、選択（`anchor`、`focus`）、IME の未確定文字列、取り消しの履歴を持つ |
| 行（子） | `div`（行の装飾のスタイル）の中に、表示用の文字列のテキストノード。ノードがあるのは見えている範囲と上下の余裕の行、キャレットの行だけで、ほかの行は高さだけの隙間の箱にまとめる（[31](31-code-editor.md) の「見えている行だけ作る」。はじめは行ごとに `content-visibility: auto` にしていたが、26 万行で 4.2 GB になったので置き換えた） |
| ブロック（子） | 複数行を 1 つのノードに置き換えたもの（表や図）。`div` の中にそのノード |

- 位置はすべてソースのバイト位置で持つ。行の表は編集のたびに作り直す（200 KB で約 20 µs）。
- 取り消しは変更（位置、消した文字、入れた文字、前後の選択）で持つ。文書全体を写さないので、大きな文書でも履歴が軽い。続けて打った文字と消した文字は 1 つにまとめる（今の `text_area` と同じ規則）。

### 装飾

```rust
pub enum Row {
    Line(Rc<LineLook>),                              // 1 行
    Block { lines: usize, style, widget: Widget },   // 何行かを 1 つのノードに
}
pub struct LineLook {
    pub style: Option<Rc<Style>>,                    // 行の箱: 左の余白、背景、左の線、文字の大きさ
    pub marks: Vec<(Range<usize>, Rc<Style>)>,       // 範囲のスタイル（行の中の位置、重ならない）
    pub raised: Vec<(Range<usize>, VerticalAlign)>,  // 上付き、下付きにする範囲（vertical-align）
    pub replace: Vec<(Range<usize>, Option<Widget>)>,// 隠す（None）か、ノードに見せる
}
pub struct Widget { pub key: u64, pub build: Rc<dyn Fn() -> View> }
```

- `decorate` は、文字列か選択が変わるたびに、文書全体の行を返す。`DecorateContext` は文字列、行の表、選択、フォーカスを持つ。
- 前の行の並びと比べ、同じもの（ソースが同じで、`LineLook` が同じ）はそのまま残す。比べるのは両端から変わったところまでなので、1 打鍵ではほぼ変わった行だけを見る。`LineLook` は `Rc` で、作る側が変わらない行に同じものを返せば、比べるのはポインタだけになる。
- 変わった行は、ノードを作り直さずに文字列とスパンだけを差し替える（整形し直すのはその行だけ）。ノード（`Widget`）を含む行とブロックは作り直す。`Widget` は `key` が同じなら作り直さない。
- 表示用の文字列は、隠す範囲を除き、置き換える範囲にインラインボックスを置き、未確定文字列を入れ、最後に空白を 1 つ足したもの。最後の空白は、空の行に高さを与え、行をまたぐ選択で改行の位置を見せる。ソースの位置との対応（区間の表）を持つ。今の `EditData` の `to_display` / `to_model` を一般にしたものである。

### 操作

- **左右:** ソースの書記素ごと。単語ごと（Ctrl）は Unicode の単語の境界で。隠す範囲は、キャレットが触れると装飾が見せるもの（Obsidian の規則）なので、キャレットは隠れた範囲に入らない。入ってしまったときは範囲の端に描く。
- **上下、Page Up/Down:** 縦の位置で動く。キャレットの上（下）の端の少し外を、覚えておいた横の位置で当たり判定する。行をまたいでも、折り返した行の中でも同じ。行の箱は文書の順に並んでいるので、縦の位置から二分探索で行を見つける。ブロックに当たったときは、そのブロックの最初（下へ）か最後の行の頭（上へ）に入る。
- **Home/End:** 折り返した見た目の行の端。Ctrl で文書の端。
- **ポインタ:** 当たった行の中で当たり判定する。2 回で単語、3 回で行を選ぶ。ブロックを押すと、そのソースの頭にキャレットを置く（装飾がソースに戻す）。押されたノードとその祖先（行まで）に `on_click` があるとき（チェックボックスなど）は、エディタは何もしない。
- 選択、未確定文字列の下線は各行のテキストノードが描き、キャレットはキャレットのある行が描く。どちらも、変わったときにエディタが行に書き込んでおく。
- 1 つのノードにした行（表、図）が選択に入っているときは、その箱に選択の色を重ねる（Chromium が選択した画像に重ねるのと同じ）。
- 選択した文字は、`text_area` と同じく運べる（[23](23-drag-and-drop.md)）。押したのが選択の塗りの上なら運ぶ準備をし、動かさずに離したらそこにキャレットを置く。同じエディタの中で動かすと 1 回で取り消せる。エディタと入力欄、エディタどうしの間でも運べ、ほかの場所に動かしたときは元の所から消す。運ばれてきた文字が落ちる位置には、行がキャレットを描く。
- キャレットのある行は、画面から遠くても `content-visibility` で飛ばさない。キャレットが見えるようにスクロールする。
- IME、クリップボード、PRIMARY の選択、中ボタンの貼り付けは `text_area` と同じ。コピーするのはソース。

### 入れないもの（今は）

- 双方向テキストの見た目どおりの左右の移動（ソースの順に動く）
- 折り返した行のぶら下げ（リストの 2 行目を字下げする）
- 複数のキャレット

## M4: `markdown_editor`

```rust
markdown_editor(source)                   // Signal<String> と双方向
    .theme(MarkdownTheme::default())
    .image(|src| resolve(src))
    .on_link(|url| open(url))             // Ctrl + クリック
```

- `text_editor` に、Markdown から作った装飾を付ける。
- Obsidian と同じく、記号はキャレット（選択）が触れている要素の分だけ見せ、それ以外は隠す。図、表、区切り線、画像、チェックボックスは、キャレットが入るとソースに戻る。
- 図、表、区切り線がソースに戻るのは、選択が全部その中にあるとき（キャレットだけのときを含む）だけにする。選択がまたいでいるだけなら見た目のまま選択の色を重ねる。選択している最中に何行もの図がソースに変わると、選んでいる所が跳ぶためである。

| もの | キャレットが外にあるとき | 触れているとき |
|---|---|---|
| `**太字**`、`*斜体*`、`~~取り消し~~`、`` `code` `` | 記号を隠し、中身にスタイル | 記号を薄い色で見せる |
| `[文字](url)` | `[`、`](url)` を隠し、文字をリンクの色に | 見せる |
| `![alt](src)` | 画像（インラインのノード） | ソース |
| `# 見出し` | `# ` を隠し、行を見出しの大きさに | `# ` を見せる（行にキャレットがあるとき） |
| `> 引用` | `> ` を隠し、行に左の線 | 見せる |
| `> [!NOTE]`（GitHub のアラート） | 線をアラートの色に、本文をふつうの文字の色に。`[!NOTE]` を名前（Note など）のノードに | `[!NOTE]` を見せる |
| `[^1]`（脚注） | `[^`、`]` を隠し、`1` を上付きのリンクの色に | 見せる |
| `[^1]: 脚注` | 同じく `1` だけを上付きに。行は小さく、薄い色に | 見せる |
| `^上付き^`、`~下付き~` | 記号を隠し、上付き、下付きに | 見せる |
| `- 項目` | `-` を「•」に | `-` |
| `- [ ] 作業` | チェックボックス（押すとソースの `[ ]` と `[x]` を入れ替える）。終わった作業の文字は `MarkdownTheme::task_done`（既定は空で、GitHub と同じくチェックが付くだけ） | ソース |
| コードブロック | 行に等幅と背景。囲みの行（` ``` `）は細く、記号を隠す | 囲みの行を見せる |
| Mermaid | 図（ブロック） | ソース（コードブロック） |
| 表 | 表（ブロック。ビュワーと同じもの） | ソース |
| `---` | 区切り線（ブロック） | ソース |

- `^上付き^` と `~下付き~` は、`pulldown-cmark` が強調と同じ規則で探すので、`a ^2^ b` のように前後に空白があるときしか見つからない（`上付き^2^と`、`H~2~O` は見つからない）。Pandoc と同じく、記号の間に空白がないものを語の中でも上付き、下付きにする（`parse::scripts`）。ビュワーも同じものを使う。`~~` は取り消し線のまま。
- 解析は打鍵のたびに文書全体を `pulldown-cmark` でし直す（速さは下の「確かめたこと」）。いちばん外側のブロックごとに、ソースと、選択がそのブロックに触れているときはその位置を鍵にして、作った行を覚えておく。変わらないブロックは同じ `Rc<LineLook>` を返すので、`text_editor` の比較はポインタで済む。
- 見た目はビュワーの `MarkdownTheme` から作る。行と行の間はソースの空行そのものなので、段落の下の余白は使わない。見出しには上の余白を付ける。
- フォーカスがないときは、何も書いていないので、すべてを見た目どおりに出す（記号を見せない）。
- キーの操作（`on_key_down` で `text_editor` より先に受ける）:
  - リストと引用の行で Enter を押すと、次の行に同じ記号（番号は 1 つ増やす。タスクは `[ ]`）を入れる。中身が空の項目で押すと、記号を消してリストを終える。
  - リストの行で Tab と Shift+Tab を押すと、項目を 4 文字ぶん字下げ、または戻す。それ以外の行では `text_editor` の Tab（選択した行の字下げ、選択がなければ空白 4 つ）になる。
- チェックボックスは、押すとソースの `[ ]` と `[x]` を `EditorRef::replace` で入れ替える（取り消せる）。覚えておいたブロックの行を使い回しても位置がずれないように、ブロックの今の先頭の位置を `Rc<Cell>` で持ち、毎回書き換える。
- Ctrl を押したままリンクをクリックすると `on_link` を呼ぶ。リンクは押した行だけを解析し直して探す。

### 確かめたこと（M3、M4）

- 単体テスト: 行頭の表と取り消し、続けて打った文字と消した文字のまとめ方、外からの文字列の差し替え（変わった範囲だけを 1 つの変更にし、キャレットは文字についていく）、単語の境界、表示用の文字列とソースの位置の対応、未確定文字列の位置とスタイル、インラインのノード（core 7 個）。リストと引用の続き、画像の部分、引用の記号、リンクを行から探すこと（markdown 4 個）。
- `Ui` を通したテスト（core の `tests/text_editor.rs` 9 個、markdown の `tests/editor.rs` 4 個）: 打鍵、Enter、取り消し、シグナルからの差し替え、上下の移動と横の位置、隠した記号の上をクリックしたときの位置、未確定文字列と確定、ブロック、複数行の選択と切り取り、記号が見える範囲、表に入るとソースになること、リストの続き、チェックボックス。
- 描いた絵で確かめた（ヘッドレスの GPU に描いて PNG にした）: 見出し、太字、斜体、コード、リンク、箇条書きの点、チェックボックス、引用、表、コードブロック、Mermaid の図。キャレット、行をまたぐ選択（空行は改行の幅だけ塗る）、未確定文字列の下線、表に入ったときのソース。
- 速さ（リリースビルド、バッテリー駆動。電源につないで測り直す）:

| | 時間 |
|---|---|
| 素の `text_editor`、5000 行を作る | 61 ms |
| 素の `text_editor`、5000 行で 1 打鍵 | 0.9 ms |
| `markdown_editor`、bench.md（214 KB、3120 行）の最初のレイアウト | 74〜82 ms（ビュワーと同じくらい） |
| 同じく、文書の中ほどで 1 打鍵 | 平均 1.3 ms、最悪 2.1 ms |
| 同じく、1 行下へ | 平均 0.8〜1.0 ms、最悪 2.4〜3.3 ms |
| 266 行のスライド（Marp、画像と絵文字入り）で 1 打鍵 | 平均 0.11 ms |
| アプリで bench.md を開いて最初の絵まで | 163〜174 ms（ビュワーは 161 ms） |
| メモリ（PSS） | 178〜179 MB（ビュワーは 177〜178 MB） |

  初めて見せる行は、そこで整形する（絵文字のフォントを初めて読むと約 80 ms かかった）。打鍵の時間は、その位置へ一度キャレットを動かしてから測った。1 打鍵のうち、装飾を作り直して行を比べるのが約 1.2 ms で、その 0.8 ms が文書全体を `pulldown-cmark` で解析し直してブロックの境目を探す時間だった。キャレットを動かすだけのときは、文字列の版が同じなので解析をし直さない。もっと速くするなら、変わったブロックから後ろだけを解析し直す（境目が前と揃ったところで止める）。

## 速さの確かめ方

同じ Markdown を `pulldown-cmark` で HTML にし、GitHub に近い CSS を付けて Chromium で開く（比べるためだけに使う）。Chromium では、`<head>` のスクリプトから、最後のスクリプトで `offsetHeight` を読んでレイアウトさせるまでの時間を測る。HTML の読み込み、DOM、スタイル、レイアウトが入る。こちらは `markdown_view` を作り始めてから、最初のレイアウトと描画が済むまでを測る（`tests/view.rs` の `time_a_long_document`、`MARKDOWN_FILE` で文書を指定する）。幅は約 980 px、リリースビルド。下の表はこの段のもの。今のテストは、幅 1000、高さ 900 のウィンドウの中でスクロールする形で測り、最後まで 1 ページずつ下へスクロールする時間と、最初の見積もりの高さも出す（[29](29-content-visibility.md) の「速さ」）。

| 文書 | Chromium | ここ | ここの内訳 |
|---|---|---|---|
| サンプルの 50 回分（48 KB、図なし） | 32〜49 ms | 74〜82 ms | フォント一覧の初期化 15、ノード 11〜18、スタイル 5、レイアウト 40（整形 29） |
| tokio の CHANGELOG.md（195 KB、4963 行） | 79〜87 ms | 133〜167 ms | 同じく、初期化 15 を含む |

この時点では 1.5〜2 倍遅く、差のほとんどは文字の整形だった（1 回 約 15 µs）。縮める方法として、見えている段落だけを整形する、整形を複数のスレッドに分ける（メモリが増える）、整形結果を使い回す、の 3 つを比べ、1 つ目を選んだ。いちばん外側のブロックを `content_visibility_auto()` と `estimate_contents()` の箱に入れ、画面から遠いブロックはレイアウトも整形もしない（[29](29-content-visibility.md)）。

tokio の CHANGELOG.md は、ウィンドウの中でスクロールする形で、154 ms から 71〜76 ms になった（バッテリー駆動で続けて測った。同じ条件の Chromium は 68〜108 ms）。1 ページ下へのスクロールは平均 1.5 ms、最悪 3 ms かかるようになった。

図は 1 つ 0.3〜3 ms で、ワーカーで作るので、最初の絵を遅らせない。

- 時間は、`grim` の画面全体のスクリーンショット（約 30 枚/秒）で、アプリの窓の中の変化の 97% が済んだ時刻。ShojiWM の窓が開くアニメーション（約 0.5 秒）はどのアプリにも入っている。

- アプリごとに使い捨てのホームディレクトリを使った。VS Code は、`.md` をプレビューで開く設定が効かなかったので、小さな拡張機能で `markdown.showPreview` を呼び、プレビューが出るまでを測った。

| AntiWebUI | ネイティブ（wgpu） | 1.61〜1.75 秒 | 175〜176 MB | 1 |

## 分かっている限界

- 表のセルは折り返さない。core に表のレイアウトがないためである。
- 段落の中の `inline` の中身（画像の中の文字など）を選択がまたぐときの順番は正しくない。
- 図はクラシックのテーマだけ。
- `merman` より mermaid.js との違いが大きい（ラベルの位置など）。
- リンクの上で押してから選択を始めると、離したときにリンクが開く。
- 画面から遠いブロックの高さは見積もりなので、スクロールバーのつまみの大きさと位置は、読み進めると少し変わる（見えている所はずれない）。
- エディタ: 双方向テキストでも左右はソースの順に動く。リストの 2 行目以降はぶら下げにならない。運ぶ文字の絵には、1 つのノードにした行（表、図）は入らない。
- エディタ: ブロックだけを解析するので、文書の別の所で定義した参照リンク（`[文字][ref]`）は、リンクとして扱わない（ビュワーは扱う）。脚注は、文書の脚注の定義を空にしてブロックの後ろに付けてから解析するので、参照として扱う。
- エディタ: setext の見出しの下線の行は、隠しても空の行として残る。
- 上付き、下付きは 1 つのスパンの中だけ（`^**2**^` のように中で強調が変わるものは見つけない）。`x^2+y^` のように記号の間に空白がないと、その間が上付きになる（Pandoc と同じ）。
- エディタ: 日本語のような複数バイトの文字で、ブロックの終わりの 1 バイト前で文字列を切ってクラッシュしていた（2026-11-06 に直した）。装飾の範囲は、`text_editor` が文字の境目に丸める。
