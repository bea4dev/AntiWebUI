# 12. transform と合成レイヤー

位置やサイズを `left` や `w` で動かすと、値が整数ピクセルに丸められ、後ろの要素を押すときはレイアウトも走る（2000 行の上の要素で 1 フレーム約 3 ms）。そこで、レイアウトに関わらず、描画の最後に掛かる変形を入れる（[01](01-pixel-model.md) の R5、R6）。

## API

```rust
div()
    .translate(12.0, 0.0)        // 論理ピクセル。translate_x / translate_y もある
    .scale(1.05)                 // scale_x / scale_y もある
    .rotate(45.0)                // 度。正は時計回り
    .transform_origin(0.5, 0.5)  // 箱に対する割合。既定は中心
```

- 順序は CSS の個別プロパティ（`translate` / `rotate` / `scale`）と同じで、`origin` を基準に、拡大縮小 → 回転 → 移動の順に掛かる。
- `hover` や `dyn_style` でも同じように書ける。プロパティが分かれているので、`hover(|s| s.scale(1.05))` が別の層の `translate` を消さない。
- 継承しない。
- レイアウトは変わらない。周りの要素から見ると、元の位置にあるのと同じ。

## 方式: 内容をテクスチャに描いて合成する

| | 合成レイヤー（採用） | プリミティブごとに行列を掛ける |
|---|---|---|
| 変形だけが変わるフレーム | 四角形 1 枚の描き直し。CPU のペイントも GPU の内容の描画も無い | 全プリミティブを毎回描く |
| 文字の拡大 | 拡大率に合わせて描き直すまでぼける | グリフをサイズごとに描くので、アニメーション中はキャッシュが溢れる |
| クリップ | 合成時に外側のクリップだけ見ればよい | 内側と外側のクリップを座標系ごとに持つ必要がある |
| シェーダーの変更 | 合成用を 1 つ足すだけ | 既存の全シェーダー（AA、クリップ）に手が入る |
| グループ不透明度、シェーダー効果 | 合成の段階にそのまま載る | 別の仕組みが要る |
| 変形した要素が多いとき | 要素ごとにテクスチャとパスが要る | 軽い |

Chromium も、アニメーションする要素は `cc` の合成レイヤーにする。Chromium は動かない変形を Skia で直接描くが、こちらは経路を 1 つにして、数が問題になったら考える。

## 場合分け

- **変形が無い（恒等）ノードはレイヤーにならない。** 今までと同じ経路で、1 ピクセルも変わらない。アニメーションが `translate(0, 0)` や `scale(1)` で終われば、最後は元の鮮明な描画に戻る。
- **整数の移動はニアレストで合成する。** テクスチャのピクセルがそのまま画面のピクセルになるので、直接描くのと同じに見える。
- **端数の移動、拡大縮小、回転はバイリニアで合成する。** 端数の移動で、ゆっくりした動きも滑らかになる。テクスチャは内容の周りに透明な 1 テクセルを持ち、そこへ向かって縁が薄れる。描く範囲はそのテクセルの半分まで（`push_layer`）。全部を描くと、さらに外側のテクセルも読んでしまい、そこには以前の内容が残っていることがある。
- **移動が止まったら整数に揃える。** 端数の移動はアニメーション中だけのものとして、変形が 1 フレーム変わらなかったら丸めて描き、文字のぼけを残さない。そのために止まった次のフレームを 1 回だけ作る。

## 拡大したときの解像度

レイヤーを描く倍率 `k` はレンダラが決める。

- `k` は拡大率以上の最小の整数（上限 4）。レイヤーの内容は整数座標なので、整数倍なら箱の角やグリフの位置がそのまま使える。
- 回転しているときは `k` を 2 以上にして、バイリニアのぼけを減らす。
- レイヤーが残っている間は `k` を下げない。拡大と縮小を繰り返しても描き直しが起きない。
- 縮小は `k = 1` のままバイリニアで合成する。ミップマップは持たないので、1/2 より大きく縮めると細い線がちらつくことがある。

## 座標系（core）

スクロールレイヤーと同じく、変形するノード `T` を座標空間にする。

- `T` の子孫と `T` 自身は `T` の空間に属する（`Node::space == Some(T)`）。座標の数値は親の空間のものをそのまま使うので、`abs` は変形の影響を受けない。
- 空間の中のクリップは `Clip::NONE` から始める。`T` より外のクリップは `Node::layer_clip` に親の座標で持ち、合成時に掛ける。
- 親の空間は `Node::outer_space` に持つ。
- `T` の空間の中にスクロールする要素があるときは、スクロールレイヤーにせず内容として描く（入れ子のスクロール要素と同じ）。逆に、スクロールレイヤーや別の `T` の中の `T` は入れ子のレイヤーになる。
- 親から見た範囲（`child_bounds` など）は、`subtree_bounds` を行列で変換した外接矩形にする。

ウィンドウ座標との変換は `Document` の次のメソッドに集める。

| メソッド | 用途 |
|---|---|
| `window_rect` | `NodeRef::rect`、ポインタイベント、ポップアップの基準。`getBoundingClientRect` と同じく外接矩形 |
| `to_window` | IME のカーソル位置 |
| `from_window` | スクロールバーのドラッグ、テキスト選択 |

ヒットテストは `T` のところで逆行列を掛けてから子へ進む。拡大率が 0 で逆行列が無いときは当たらない。

## 差分とキャッシュ

- `dirty.content` は、計算済みスタイルが実際に変わったときに `resolve_node` で立てる（今までは無効化の時点で立てていた）。`T` のまま変形と不透明度だけが変わった場合は立てない。
- ただし、外側のレイヤーの内容には内側の行列が含まれるので、外側だけを `stale_layers` に入れて描き直す。内側の内容（`Arc<Scene>`）はそのまま再利用される。
- レイヤーの範囲（`Layer::bounds_on_parent`）は、内容の範囲を行列で変換した外接矩形と、外側のクリップの交わり。行列か不透明度が変わったら、前後の範囲を変更矩形にする。
- 恒等とそれ以外の切り替えでは、子孫のクリップと空間が変わるので位置計算を走らせる。
- 変形で要素がポインタの下に来たり離れたりするので、変形が変わったらホバーを判定し直す。

`T` の `opacity` は、子孫の色に掛けず、合成時に掛ける。不透明度のアニメーションで内容を描き直さないうえ、CSS と同じグループ不透明度になる。

## グループ不透明度

CSS の `opacity` は、中身を 1 枚の画像にしてから透かす。子孫の色に掛けるだけだと、重なった部分が透けて見える。

| ノード | 方法 | 理由 |
|---|---|---|
| 描くものが 1 つ以下（文字だけ、背景だけなど） | 今までどおり色に掛ける | 重ならないので結果は同じ。テクスチャが要らない。半透明の文字がたくさんあっても軽い |
| 描くものが 2 つ以上（背景と文字、影と箱、入力欄など） | レイヤーにして合成時に掛ける | 重なり得る |

判定は木の構造だけで行い、見えている範囲には依存しない（Chromium の effect ノードで、重なりが無ければ render surface を作らないのと同じ考え方）。

変形のノードと違い、座標の空間は変えない。テクスチャに描く座標がそのまま親の座標なので、ヒットテスト、位置計算、内側のクリップは何も変わらない。`opacity` が 1 と 1 未満の間で変わっても位置計算は走らない。

不透明度だけが変わるフレームは、内容（`Arc<Scene>`）を再利用する。ただし内側に別のレイヤーがあるときは、その変化を知る方法が無いので、ペイントだけやり直す（テクスチャの描き直しは差分だけで済む）。

合成時の不透明度は 8bit に丸める。色と同じく、8bit で区別できない変化では描き直さない。

### 計測

変更前（子孫の色に掛ける）と変更後の、1 フレームの時間（1620×1616、スケール 1.8、RTX 5070、ms）。

| 場面 | 変更前 | 変更後 |
|---|---|---|
| パネル全体（背景と 55 行）をフェード | 0.26〜0.27 | 0.09〜0.10 |
| 55 行（背景と文字）を同時にフェード | 0.24〜0.26 | 0.19〜0.20 |
| フェードしている行が 55 行のうち 1 行 | 0.08〜0.09 | 0.06〜0.07 |
| 文字だけの 55 行をフェード（レイヤーなし） | 0.16〜0.17 | 0.15〜0.16 |
| 3 行に 1 行が半透明のリスト（2000 行）のスクロール | 0.10〜0.11 | 0.12 |

最初のフレームは、半透明の行が 55 行あると 2.3〜2.7 ms が 3.4〜4.0 ms になる（テクスチャの確保と内容の描画）。

代わりに GPU メモリを使う。1 行（1620×29）で 1664×32 の約 210 KB、55 行で約 12 MB（計算値）。背景が無く文字だけの行はレイヤーにならないので使わない。

## レンダラ

- `Primitive::Layer`（旧 `ScrollLayer`）は `transform`、`bounds`、`opacity` を持つ。スクロールは `origin` だけが変わる。
- トーラスのテクスチャはそのまま使う。サンプラを Repeat にしたので、バイリニアでもテクスチャの端をまたいで正しい隣のピクセルを読む。
- テクスチャに描く範囲は、外接矩形を逆行列で戻した範囲に 1 ピクセルの余白を足す。余白は透明なので、回転した辺はバイリニアで自然に滑らかになる。辺のための AA は持たない。
- レイヤーの入れ子は、内側を先に描く（後順）。外側の描き直す範囲に掛からない内側は描かない。
- 合成は専用のパイプライン（`vs_layer` / `fs_layer`）で行う。入力は行列、テクスチャ、外側のクリップ、不透明度。

## 計測

1 枚のカード（400×260、影、10 行の文字）を、2000 行のリストの前で動かしたときの 1 フレームの時間（1620×1616、RTX 5070、電源接続、ms）。

| 動かし方 | update | paint | diff | record | GPU | 計 |
|---|---|---|---|---|---|---|
| `mt`（後ろのリストを押す） | 0.26 | 0.02 | 0.02 | 0.09 | 0.05 | 0.43〜0.46 |
| 絶対配置の `left` | 0.00 | 0.02〜0.04 | 0.02〜0.03 | 0.07〜0.12 | 0.04〜0.05 | 0.15〜0.24 |
| `translate` | 0.00 | 0.02 | 0.01 | 0.03〜0.04 | 0.04〜0.05 | 0.10〜0.11 |
| `scale` | 0.00 | 0.02 | 0.01 | 0.03 | 0.04 | 0.09 |
| `rotate` | 0.00 | 0.01〜0.02 | 0.01 | 0.04〜0.05 | 0.04 | 0.10〜0.11 |
| `opacity`（レイヤーあり） | 0.00 | 0.02 | 0.01 | 0.03〜0.04 | 0.04〜0.09 | 0.10〜0.15 |
| `opacity`（レイヤーなし） | 0.00 | 0.02〜0.03 | 0.02 | 0.08〜0.09 | 0.04〜0.09 | 0.16〜0.23 |

- レイヤーを作る最初のフレームは 0.26〜0.68 ms（内容を描いてテクスチャを確保するので）。
- `mt` の 0.26 ms は、行が `flex_none` で縮まない場合。行が既定の `flex_shrink` のままだと、同じ 2000 行で約 3 ms だった（冒頭の値）。
- どの動かし方も 1 ms に届かない小さな場面なので、差の絶対値は小さい。
- 実機（ShojiWM、120 Hz）で 3 枚のカードを 4 秒動かしたときは、`translate` もレイアウトも 118 fps 前後で差が無かった（どちらも 1 リフレッシュより十分軽い）。
- レイヤーを使わない経路は変わらない。`bench_scroll` と `bench_changes` の値は変更前と同等だった。

レイヤー 1 枚につき、表示範囲の GPU メモリを使う（400×260 論理、スケール 1.8 で約 2 MB、回転中は `k = 2` でその 4 倍）。

## カスタムシェーダーへの備え

「塗り」は [14](14-shaders.md)、「効果」は [16](16-filters.md) で実装した。

カスタムシェーダーには 2 種類あるが、どちらも今回の構造に載る。

| 種類 | 例 | 入れる場所 |
|---|---|---|
| 効果: 描いた内容を入力にする | ブラー、色調、波打ち | `Layer` に効果を持たせ、`fs_layer` の代わりに使う。ノードを変形と同じくレイヤーにする条件を増やすだけ |
| 塗り: 箱の中を自分で塗る | グラデーション、ノイズ、3D ビュー | 新しい `Primitive` を足す。`Batch` と差分の仕組みはそのまま使える |

効果のために決めておくこと:

- テクスチャの範囲は、効果がはみ出す分（ブラーの半径など）だけ `bounds` を広げる。
- 時間で変わる効果の入力（uniform）は、行列と同じく内容の外に置き、内容を描き直さずに差分だけ出す。

## やっていないこと

- 3D の変形、`skew`、遠近法。
- 変形したノードが多いときの直接描画（数が問題になったら）。
- テクスチャの使い回し。
- ミップマップ（大きな縮小）。
- 変形の中のスクロール要素を別レイヤーにすること。
