# 30. パフォーマンスオーバーレイ

アプリを動かしながら、フレームにかかった時間と、先行描画（[10](10-frame-pacing.md) の `FrameAdvance`）の状態を、ウィンドウの右上に出す。Chromium の「Frame Rendering Stats」に当たる。どのアプリでも使える、AntiWebUI の標準の機能である。

## 使い方

```rust
App::new()
    .settings(|s| s.debug.performance_overlay = true)
    .run(root)?;
```

- 環境変数 `ANTIWEBUI_PERF_OVERLAY=1`（`0` で消す）で、プログラムを変えずに出せる。設定より優先する。
- `update_settings(|s| s.debug.performance_overlay = …)` で、動かしながら出し入れできる（デバッグ用のメニューなど）。

## 出すもの

```
 60 fps  16.7 ms
 CPU  3.2 ms  (UI 2.5)
 GPU  1.4 ms
 latency 21.0 ms
 Advance  Auto: on
 ▁▁▂▁▁█▁▁▁▁▁▂▁▁   フレームの間隔（リフレッシュの線つき）
 ▂▃▂▂▅▂▂▃▂▂▂▂▂▂   CPU（青）と GPU（橙）
```

| 行 | 中身 |
|---|---|
| fps | 画面に出たフレームの間隔（`presented` の差）の、直近 30 フレームの平均から。100 ms を超える間隔は一時停止として数えない |
| CPU | フレームを作り始めてから submit と commit までの時間（`end - start`）。括弧はそのうちの UI の部分（スタイル、レイアウト、シーンを作る）。直近 30 フレームの平均 |
| GPU | GPU がそのフレームに使った時間の目安: 描き終わり（sync_file）から、submit と前のフレームの描き終わりの遅い方を引いた時間。先行描画で前のフレームを待っていた時間を含めないため。直近 30 フレームの平均。時刻が取れない経路（wgpu Surface）では `-` |
| latency | 作り始めてから画面に出るまで（`presented - start`） |
| Advance | `FrameAdvance` の設定。`Auto` のときは今の状態（`on`、`off`、`trying`、`off (no gain)`）。環境変数で上書きしているときは `(env)` を付ける。最後のフレームが実際に先行して描かれていた（commit が次のコールバックまで待った）ときは `, ahead` を付ける |

グラフは直近 90 フレームの棒で、上は間隔（リフレッシュより長いものは赤）、下は CPU と GPU を並べる。横線はリフレッシュの周期。縦の目盛りはリフレッシュの 2 倍まで（それより長いものは頭打ち）。

## 作り方

- **ノードを使わない。** オーバーレイはアプリの木に入らず、レイアウトも当たり判定もない。アプリの計測を乱さないためである。アプリ（`anti-webui-app`）が、窓のシーンを渡す直前に、core の `PerformanceOverlay::paint` でプリミティブ（四角形と文字）を足す。
- 足したプリミティブは自分の `ChunkKey`（`node: u64::MAX`）を持つので、変更範囲はオーバーレイの四角形だけになる。
- 数字の元は、`ANTIWEBUI_FRAME_STATS` と同じ `FrameRecord`。コンポジタが表示を伝えてきた後で分かるので、1〜2 フレーム遅れて出る。
- **オーバーレイのためにフレームを増やさない。** フレームはアプリが描くときにだけ来る。ただし止まる直前の数フレームの結果は次のフレームまで届かないので、アプリが止まったら 1 回だけ、200 ms 後にオーバーレイのためのフレームを描く。このフレームは数字に入れない。
- 文字は等幅、11 論理ピクセル。整形した結果は文字列が同じ間は使い回す。

## 確認したこと

- 数字の作り方（間隔、CPU、UI、GPU、遅延、先行したか）と、オーバーレイ自身のフレームを数えずに次を求めないことは、`anti-webui-app` の単体テストで確かめた。
- 先行したかは、commit がそのフレームの処理の後（次のフレームのコールバック）だったかで判断する。`committed` はすぐ commit したフレームにも入っているため、0 かどうかでは分からない。
- 重さ: `bench_pacing --rows 2000`（120 Hz、毎フレームスクロール）で、`ANTIWEBUI_FRAME_STATS` の CPU の中央値が 0.53〜0.55 ms から 0.65〜0.73 ms になった（主にプリミティブが増えた分の記録）。GPU の時間は変わらず、リフレッシュは飛ばなかった。
- 出していないときは、シーンにもフレームにも何も足さない。

## 分かっている限界

- Wayland のランナーだけ。ヘッドレスとほかのプラットフォームには、プラットフォームができたときに足す。
- 先行の数（`Custom` で 2 枚以上）は出さず、先行したかどうかだけを出す。
