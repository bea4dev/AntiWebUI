# 14. カスタムシェーダー

WGSL で書いたシェーダーで、要素の箱の中を塗る。箱の値（サイズ、枠線、パディング、角丸）はレイアウト後の物理整数ピクセルのまま渡る。

今回の範囲は**箱の中を塗る段（`fill`、`overlay`）**までで、描いた内容や背後を入力にする段（`filter`、ブラー、backdrop）は次の段階で足す。

## API

```rust
use anti_webui::prelude::*;

#[derive(ShaderParams, Clone, Copy)]
struct Aurora {
    time: f32,
    color: Color,
}

// 名前はエラーメッセージに使う
static AURORA: Shader<Aurora> = Shader::new("aurora", include_str!("aurora.wgsl"));

shader(move || AURORA.params(Aurora { time: t.get(), color: rgb(0x55ccff) }))
    .w(320.0).h(180.0).rounded(16.0).p(12.0)
    .border(2.0).border_color(rgb(0xffffff))
    .child(text("Hello"))
```

```wgsl
// aurora.wgsl: `paint` だけを書く。`params` の struct は derive から生成される
fn paint(f: Frag) -> vec4<f32> {
    let origin = vec2<f32>(f32(aw_box.border.w), f32(aw_box.border.x));
    let inner = vec2<f32>(aw_box.size - aw_box.border.wx - aw_box.border.yz);
    let uv = (f.px - origin) / inner;
    let wave = 0.5 + 0.5 * sin(uv.x * 8.0 + params.time);
    return params.color * wave;   // 出力はプリマルチプライド
}
```

### 描く段

| 段 | API | 描かれる位置 | 主な用途 |
|---|---|---|---|
| 塗り | `.fill(f)` | 外側の影の上、`bg` の下 | グラデーション、進捗バー、ノイズ |
| 重ね | `.overlay(f)` | `bg`・枠線・内側の影の上、子の下 | 状態レイヤー、リップル |

- `shader(f)` は `div().fill(f)` の短縮形。
- どちらも枠線を含む箱（border box）の角丸で切り抜く。アンチエイリアスとクリップはフレームワークが掛けるので、シェーダーは形を気にしなくてよい。
- `f` は `ShaderPaint` か `Option<ShaderPaint>` を返すクロージャ。読んだシグナルが変わったときだけ走る（`dyn_style` と同じ）。`None` の間は何も描かない。押されていないボタンにコストは掛からない。
- 当たり判定は箱のまま。

### シェーダーに渡る値

```wgsl
struct AwBox {
    size: vec2<i32>,     // 枠線を含む箱のサイズ
    border: vec4<i32>,   // 上・右・下・左
    padding: vec4<i32>,  // 上・右・下・左
    radii: vec4<f32>,    // 左上・右上・右下・左下
    scale: f32,          // UI スケール（論理 → 物理ピクセル）
}

struct Frag {
    px: vec2<f32>,       // 箱の左上からの物理ピクセル。画素の中心は .5
    ipx: vec2<i32>,      // 同じ位置の整数座標
    pixel: f32,          // 出力の 1 画素が何ピクセルか。アンチエイリアスの幅に使う
}
```

`aw_box.size` と `aw_box.border` は矩形パイプラインに渡す値と同じなので、枠線との境目がピクセル単位で揃う。

レイヤーの倍率 `k`（[12](12-transform.md)）が 1 より大きいとき、テクスチャは `k` 倍で描くが、`aw_box` と `f.px` の単位は変わらない。代わりに `f.pixel` が `1 / k` になり、`f.px` は整数間隔ではなくなる。

用意する関数:

| 関数 | 内容 |
|---|---|
| `aw_shape_distance(px)` | 箱の形までの符号付き距離（内側が負）。自由な形を足すときもこの関数を入口にする |
| `aw_coverage(distance, pixel)` | 距離からアンチエイリアスされた被覆率を求める |
| `aw_rounded_box_distance(p, rect, radii)` | 任意の角丸矩形までの距離 |
| `aw_padding_rect()` / `aw_content_rect()` | 枠線の内側、パディングの内側の矩形（`x, y, w, h`） |

`Params`、`params`、`aw_` で始まる名前、`Frag`、`AwBox` は予約する。

### パラメータ

`#[derive(ShaderParams)]` が WGSL の `struct Params` とバイト列への書き出しを生成する。WGSL の配置規則（`vec3` と `vec4` は 16 バイト境界など）をフレームワークが扱うので、パディングのずれは起きない。

| Rust | WGSL |
|---|---|
| `f32` / `i32` / `u32` | 同じ |
| `[f32; 2]` / `[f32; 3]` / `[f32; 4]` | `vec2<f32>` / `vec3<f32>` / `vec4<f32>` |
| `Color` | `vec4<f32>`（プリマルチプライド） |
| `[[f32; 4]; N]` | `array<vec4<f32>, N>` |

内部の表現は「フィールド名と型の一覧」と「バイト列」なので、C++ / C# からはこの 2 つを直接渡す形で同じものを使える（M3）。

### 実行時の扱い

- シェーダーは `static` に置くだけでよく、レンダラへの事前登録は要らない。外部のクレートからそのまま使える。
- 最初に使うときにコンパイルする。最初の押下で止まらないように、`AURORA.preload()` で次のフレームの前にコンパイルさせられる。
- コンパイルエラーは、ユーザーの WGSL の行番号を付けて標準エラーに 1 度だけ出し、その後は何も描かない。パニックはしない。
- `anti_webui::wgpu::check_shader(&AURORA)` は GPU 無しで検証するので、ユニットテストに書ける。

## 方式

### Scene

```rust
Primitive::Shader(ShaderDraw {
    paint: ShaderPaint,       // シェーダーとパラメータのバイト列
    rect: RectI,              // 箱
    border: [i32; 4],
    padding: [i32; 4],
    radii: [f32; 4],
    scale: f32,
    opacity: f32,
    clip: Clip,
})
```

他のプリミティブと同じくクリップを自分で持つ。範囲は `rect ∩ clip.rect`。比較はシェーダーの同一性とバイト列なので、パラメータが変わらなければ変更矩形は出ない。

### 差分

| 変化 | 描き直す範囲 |
|---|---|
| パラメータ | 箱だけ |
| `None` ↔ `Some` | `overlay`: 箱だけ（チャンクを分ける）。`fill`: 箱のチャンク全体 |
| 何も変わらない | なし。止まっていれば 1 フレームも作らない |

時間で動かす場合もシグナルで明示する。暗黙に毎フレーム走るシェーダーは無い。

### ペイントの省略

アニメーションで毎フレーム `dirty.content` を立てると、すべてのレイヤーの描画リストを作り直すことになる。そこで、パラメータが変わったときは `dirty.paint` だけを立て、そのノードを含むレイヤーだけを `stale_layers` に入れる。関係ないレイヤーの `Arc<Scene>` はそのまま再利用される。

### グループ不透明度

`fill` と `overlay` は「描くもの」として数える（[12](12-transform.md)）。`bg` や文字と重なるので、`opacity` が 1 未満なら要素全体がレイヤーになる。重ならない場合はインスタンスの `opacity` を掛ける。

### レンダラ

組み立てるソース:

```
custom_prelude.wgsl   Frag、AwBox、関数
struct Params { ... }  derive から生成（先頭に @align(16)）
ユーザーの WGSL        fn paint(f: Frag) -> vec4<f32>
custom_entry.wgsl     頂点シェーダーと、paint を呼ぶフラグメントシェーダー
```

同じシェーダーが続く部分は 1 回のドローコールで描く。

| | 同じシェーダーが続くとき | 別のものを挟むとき |
|---|---|---|
| パイプラインの切り替え | なし | あり |
| ドローコール | 1 回 | それぞれ 1 回 |

パラメータはインスタンスごとの添字で読む。

- シェーダーごとに uniform バッファを 1 本持ち、16 KiB の区画に分ける。16 KiB は全バックエンドで使える binding の大きさの下限。
- WGSL 側は `array<Params, N>`。`N = 16 KiB / Params の大きさ`。
- 区画をまたぐところでバッチを分け、dynamic offset で次の区画を指す。

ストレージバッファにしないのは、GL への縮退でも同じ経路で動くようにするため。

`Batch::Shader` は既存のバッチと同じく Scene の順に並ぶので、重なり順は変わらない。レイヤーの中でも同じ経路を通る。

コンパイルは `naga` で先に検証する。エラーの行番号からプレリュードの行数を引いて、ユーザーのファイルの行番号で出すため。

## カスタムシェーダーを追加しても変わらないこと

- `Primitive::Shader` が無いシーンでは、インスタンスもパイプラインも作らない。
- 標準の影、箱、文字はこれまでと同じパイプラインで描く。

## 次の段階に向けて決めてあること

- 入力を取る形は `AURORA.params(...)` が返す `ShaderPaint` に `.inputs([...])` を足す。`Image::content()` や `Image::backdrop()` もこの型へ合流させる。
- シェーダーからの形の参照は `aw_shape_distance` に統一してあるので、角丸以外の形を入れてもシェーダーは変わらない。
- カスタム影は `Primitive::Shader` に切り抜き（`cut`）と描く範囲（`extent`）を足す形で載る。今回は入れない。

## 確認

自動テスト:

- `anti-webui-app/tests/shaders.rs`: 物理整数の値の受け渡し、端数スケールでの画素位置、角丸とクリップが `bg` と一致すること、描く順番、不透明度、レイヤーの倍率、コンパイルエラー、区画をまたぐ多数のパラメータ、部分描画と全面描画の一致。
- `anti-webui-core/tests/shaders.rs`: 再実行の条件、パラメータが同じなら描き直さないこと、関係ないレイヤーの再利用。
- `anti-webui-core/tests/incremental.rs`: ランダムな操作の中で `fill` と `overlay` を切り替える。

## 性能

2026-11-03。NVIDIA GeForce RTX 5070 Laptop（コンポジタも NVIDIA）、ShojiWM、120 Hz、スケール 1.8、900×900。電源接続。`bench_shaders` と `ANTIWEBUI_FRAME_STATS` で、起動後 4 秒を除いた 7 秒の中央値。プロセスの CPU は 1 コアを 100% とする。各 2〜5 回。

### 箱ごとのコスト

すべての箱が毎フレーム色を変える。すべて 119.8〜119.9fps で、飛ばしは問題にならなかった。

| 負荷 | CPU | UI（ms） | フレームの CPU（ms） | 記録から GPU 完了（ms） |
|---|---|---|---|---|
| `bg` 1000 個 | 16.5〜19.0% | 0.95 | 1.31 | 0.22 |
| シェーダー 1000 個 | 14.7〜16.7% | 0.65 | 1.14 | 0.23 |
| 2 種類を交互に 1000 個 | 23.8〜25.6% | 0.59 | 1.80 | 1.06 |
| 計算の多いシェーダー 1000 個 | 16.8〜18.6% | 0.89 | 1.38 | 0.24 |
| 全面 `bg` | 6.2〜6.4% | 0.04 | 0.36 | 0.35 |
| 全面シェーダー | 6.2〜6.7% | 0.03 | 0.38 | 0.36 |
| 全面の計算の多いシェーダー | 6.4〜6.7% | 0.03 | 0.42 | 0.37 |
| `bg` 1 個 + 動かない行 2000 | 8.5〜9.0% | 0.19 | 0.58 | 0.26 |
| シェーダー 1 個 + 動かない行 2000 | 6.4〜6.7% | 0.03 | 0.38 | 0.31 |

- シェーダーの箱は標準の `bg` と同等か少し安い。`dirty.paint` だけで済むので、動かないものが多いほど差が出る（行 2000 で UI が約 6 分の 1）。
- 別のシェーダーを挟むコストは、1000 回の切り替えで CPU 約 0.7 ms、GPU 約 0.8 ms。1 回あたり約 1.5 µs。

### 1 ピクセルのコスト

全面の箱（1584×1584 物理ピクセル）を 40 枚重ね、オフスクリーンで描く時間から求めた、1 枚あたりの時間。読み戻しを含む時間の差なので目安。

| 1 枚あたり（ms） | `bg` | 色を返すシェーダー | 計算の多いシェーダー（sin と cos を 4 回） |
|---|---|---|---|
| RTX 5070 Laptop | 0.03 | 0.03 | 0.04 |
| Radeon 880M | 0.03 | 0.09 | 0.14 |

内蔵 GPU では、シェーダーの箱は `bg` の約 3 倍。形の距離の計算が全ピクセルに掛かるためと考えられる（未確認）。全面に 1 枚敷いても 0.1 ms 程度なので、今は対策しない。

### コンパイル

新しいプロセスで最初のフレームを描く時間を測り、2 回目との差を求めた。ドライバのディスクキャッシュを無効にした場合（冷）と有効な場合（温）。

| | md3e の 3 シェーダー、冷 | 同、温 | 比較: デバイス作成 |
|---|---|---|---|
| RTX 5070 Laptop | 約 44 ms | 約 4 ms | 約 160 ms |
| Radeon 880M | 約 15 ms | 約 4 ms | 約 75 ms |

実ウィンドウで、プリロードしない計算の多いシェーダーを動作中に初めて出すと、そのフレームの CPU は冷で 21〜35 ms、温で 3.5〜3.8 ms（各 3 回、NVIDIA）。冷はドライバの更新後などの初回だけ。


**未計測:** 内蔵 GPU をコンポジタの出力にした状態と 60 Hz。ここでの内蔵 GPU の値はオフスクリーンのもの。

## やっていないこと

- `filter`、`Image`、ブラー、backdrop、カスタム影。
- 前フレームの結果を入力にすること（`Image::previous()`）。
- パイプラインキャッシュのディスク保存。
- コンピュートシェーダー、WebGPU を直接触る `canvas`。
