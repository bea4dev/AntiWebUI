# 03. レイアウト

taffy の丸め（`round_layout`）は辺をスナップする B 方式であり、整数化と余りの分配はアルゴリズム内部で行う必要があるため、**レイアウトエンジンは自前で実装する**。全ての計算は物理 px の `i32`。

## サポート範囲（v1）

| 項目 | 内容 |
|---|---|
| display | `Flex`, `Block`（= 縦積み・幅いっぱい）, `None`, `Contents`（Fragment 用） |
| flex | `direction`（row/column）, `wrap`, `justify_content`, `align_content`, `align_items`, `align_self`, `gap`, `grow`, `shrink`, `basis` |
| サイズ | `width/height/min/max`（`Px` / `Percent` / `Auto`） |
| 余白 | `margin`, `padding`, `border` |
| position | `Relative`, `Absolute`（`inset`、親のパディングボックス基準） |
| z_index | 重なり順。レイアウトには影響しない（[09](09-shadows-stacking-popups.md)） |
| overflow | `Visible`, `Hidden`, `Scroll`（スクロールオフセットは物理 px 整数） |

未対応（後回し）: Grid, `order`。

## アルゴリズム概要（Flex）

1. 子ごとに flex base size（basis → 主軸サイズ → 内容サイズ）を整数で求め、min/max でクランプした仮サイズを得る。basis を指定し、主軸の最小サイズを指定していない項目は、CSS の `min-width: auto` のとおり内容の最小サイズ（min-content）より小さくしない（主軸方向にスクロールする項目は除く）。内容から決まる basis はそれより小さくならないので、測らない。
   - `flex_1()` は CSS の `flex: 1`（`flex: 1 1 0%`）。大きさの決まった容器では、中身の大きさに関係なく余りを分け合う。大きさの決まっていない容器（中身で幅が決まるメニューなど）では、0% が解決できないので中身の大きさになる。2026-11-06 までは `flex-grow: 1` だけで basis が中身の大きさのままだったため、中身の大きな項目（Markdown のプレビュー全体など）を毎回測っていた（[32](32-markdown-split.md)）。
2. `free = 内側主軸サイズ − Σ外側仮サイズ − gap 合計`。
3. `free > 0` かつ grow 合計 > 0 なら伸長、`free < 0` かつ shrink があれば縮小。いずれも **整数分配** と min/max の **凍結ループ** を行う。
4. 交差軸: `stretch` なら内側交差サイズ、そうでなければ内容サイズ。`align` で配置。
5. 余った主軸空間を `justify_content` で配置（space-between 等の隙間も整数分配）。

## 折り返し（`flex-wrap`）

`anti-webui-core/tests/data/flex_wrap.txt` の 82 ケースを Chromium の結果と比べている（`tools/chrome_layout.py` が書く）。Chromium が小数になるところは 1 px までの差を認める。

- **行分け:** 仮サイズと `gap` を足していき、主軸に収まらなくなったら次の行へ。行ごとに伸縮と `justify_content` を行う。
- **最小サイズ:** `flex-basis` を指定した項目は、内容の最小サイズ（`min-width: auto`）まで含めて行を決める（折り返さない容器でも同じ最小サイズを守る）。
- **`align_content`:** 交差軸に余りがあれば行に配る。既定の `Stretch` は余りを行に等分する。1 行だけでも折り返しのある容器は複数行として扱う。
- **`wrap-reverse`:** 行と項目を交差軸で反転する。マージンは物理的な辺に付いたまま。
- **高さが決まっていない縦の容器:** 折り返さない。`max-height` があればそこで折り返し、高さは列の高さになる。

### `fit-content`

幅が決まっていない横の容器（`items_start` の親の中など）は、収まらないとき、使える幅を取る。

| 容器 | 幅 |
|---|---|
| 折り返しあり | 使える幅と、最大の項目の広い方 |
| 折り返しなし | 使える幅と、項目の min-content の合計の広い方。そこから縮む |

あわせて、横の項目の基準サイズを max-content にした。以前は使える幅で頭打ちにしていて、`flex-shrink: 0` のときや、基準サイズに比例して縮むときの結果が CSS と違っていた。逆順の方向では、マージンが逆の辺に付いていた問題も直した。

## 整数分配

```rust
/// `total` を `weights` に比例して整数で分配する。合計は必ず `total` に一致する。
fn distribute(total: i32, weights: &[f32]) -> Vec<i32>
```

- **重みが均等**: `q = total / n, r = total % n`。先頭から `r` 個に +1。
  - コンテナを 1px 広げると +1 が 1 つ増えるだけで、どの子も縮まない（単調性）。
- **重みが不均等**: 除数方式（Sainte-Laguë / Webster）。`i` 番目に配る優先度 `w_i / (2 a_i + 1)` が最大の子に 1px ずつ配る（実装上は、まず `floor` で大部分を配り、残りを優先度順に配る）。
  - 最大剰余法と異なり、合計を増やしたときに誰かが減る逆転（アラバマのパラドックス）が起きない。
  - 同点はインデックスが小さい方を優先し、決定性を保つ。
- **負の分配（縮小）**: 絶対値を分配して符号を戻す。

## 内容サイズ（intrinsic size）

- テキスト: 指定幅で行分割した結果の `(ceil(width), 行高さ合計)`。min-content / max-content は parley の `calculate_content_widths`。
- 要素: 子の内容サイズから再帰的に求める。結果はノードにキャッシュし、スタイル・テキスト・スケールの変更で無効化する。

## 差分レイアウト

- ノードに変更（レイアウトに影響するスタイル、テキスト、子の増減）があると、そのノードから根までを dirty にする。
- dirty でないノードは計測キャッシュ（入力 → サイズ）と、前回の配置結果（入力・サイズ）を保持する。同じ入力で配置を求められた clean な部分木は、子孫を含めて再計算しない。位置は親基準なので、そのまま使える。
- 色・影・不透明度など、レイアウトに影響しないスタイルの変更ではレイアウトを走らせない。
- テキストは計測のために別の幅で折り返しても、計測後に描画用の折り返しへ戻す（`TextLayout::restore_final`）。
- スケール変更時はすべてのキャッシュを破棄する。
- 正しさは「差分更新の結果 = キャッシュを全部捨てた再計算の結果」をテストで検証している。

## クリップ

- `overflow` が `visible` 以外の要素と入力欄は、パディングボックスで子をクリップする。
- 角丸の要素では、内側の角丸半径（半径 − 枠線幅）でクリップする。シェーダで角丸形状のカバレッジを掛けるので、角もアンチエイリアスされる。
- 角丸のクリップ同士が重なる場合は、小さい方の形を使う（積集合の近似）。
- ヒットテストは矩形で判定する（角の外側の数ピクセルもヒットする）。

## ヒットテスト

ペイント順の逆順に、クリップ（overflow hidden/scroll）とスクロールオフセットを考慮して判定する。座標は物理 px（f32 → floor で整数）。
